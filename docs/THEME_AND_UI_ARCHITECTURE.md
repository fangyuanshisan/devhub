# DevHub 主题与 UI 架构

[返回文档大纲](README.md)

更新时间：2026-05-10

## 文档目的

本文档用于约束 DevHub 前台和后台的 UI/UX 架构方向，确保当前实现保持统一、克制、清爽，同时为后续多主题、多站点、多频道配置保留扩展空间。

## 产品定位

DevHub 当前定位为 **Core + 插件 的开源服务底座**。默认社区能力是 Core 基础能力之一，但不是项目唯一边界。

这意味着：

- DevHub 可以作为默认站点品牌存在，但前台架构不应假设自己永远只是某一个固定技术社区。
- Core 提供稳定的账号、权限、内容、SEO、后台治理和插件生命周期能力；插件可以在受控边界内扩展前台页面、后台菜单、slot、配置、主题和垂直业务 UI。
- 当前蓝白科技风是默认主题 `default-blue`，不是唯一视觉风格。
- 前台的站点名称、Logo、Slogan、导航、内容类型、首页模块、主题颜色应具备配置化能力。
- 内容呈现应优先服务社区讨论、问答、文档、项目与协作体验，而不是绑定某一门具体技术。

## 主题原则

- 当前默认主题保留现有蓝白现代社区风，作为 `default-blue`。
- 主题能力优先基于 CSS Variables 扩展，不在业务组件内写死品牌色。
- 深色模式属于同一主题下的模式切换，不等于独立主题体系已完成。
- 后续新增主题时，应尽量只替换 token 层和少量主题壳组件，而不是重写业务组件。

## 可配置范围

以下字段应被视为“可配置”，当前即使部分仍有静态兜底，也不应在基础组件中写死为唯一值：

- 站点名称：如总站名、子站名、前台标题。
- 站点 Logo：文字 Logo、图形 Logo、子站缩写。
- Slogan / 描述：总站介绍、子站介绍、首页副标题。
- 导航：顶部主导航、子站切换、频道入口。
- 内容类型：如社区、问答、文档、Wiki、项目、作品、招聘等。
- 首页模块：频道卡、精选、推荐、热门、标签云、公告、活动用户等。
- 主题颜色：品牌主色、强调色、背景、边框、按钮态、徽章态。

## 数据来源边界

UI 设计和实现需要明确区分三类来源：

### 1. 站点配置

适合来自站点配置或默认配置模块：

- 站点名、Logo、Slogan
- 顶部导航项
- 默认首页模块顺序
- 默认主题名和主题 token
- 默认文案兜底

### 2. 业务数据

必须来自业务接口或真实数据：

- 子站列表、子站状态、子站主题色
- 板块 / 分类
- Topic / 搜索结果 / 标签 / 公告
- 版主信息、活跃用户、统计数据
- 用户头像、昵称、通知数

### 3. 基础组件内部约定

基础组件只处理结构、状态和交互，不感知具体社区品牌：

- Button / Card / Badge / Tabs / Avatar / Input / Pagination / EmptyState
- 组件内部不写死 `DevHub`、`PHP`、`Go`、`Java`、`AI` 等专属文案
- 组件颜色、圆角、阴影、间距优先读取 token

## 组件分层

前台 UI 组件分为三层：

### 基础组件

职责：只负责通用交互和视觉基础能力，不感知社区业务语义。

建议范围：

- Button
- Card
- Badge
- Tabs
- Avatar
- Input
- Pagination
- EmptyState

### 社区业务组件

职责：组合基础组件和业务字段，承载社区场景。

建议范围：

- SiteHeader
- SiteSwitcher
- ContentCard
- ContentFeed
- TagCloud
- BoardList
- AnnouncementCard
- ActiveUserList

### 页面模板

职责：组织页面布局、模块区域和 SEO / 数据装配。

建议范围：

- 首页
- 子站页
- 搜索页
- 内容详情页
- 用户中心页

## 当前仓库落地约束

当前实现需要持续遵守以下边界：

- `default-blue` 只是默认主题，不得在文档或组件中描述为唯一主题。
- `/topics/:id`、`/c/:slug`、`/tags/:tag` 等 Go 动态 SEO 页面职责不变。
- 首页、搜索页、发布页等 Astro 页面可以继续作为静态壳 + 运行时增强。
- 不修改数据库结构来实现主题化。
- 不新增复杂后台主题配置功能。
- 不破坏现有 API、权限、路由和 SEO 输出。

## 后台导航信息架构

后台（`/admin-next`）导航采用“功能域分层”，用于在功能持续增长时保持可扩展性与可维护性：

- 一级导航：系统大模块（如 首页 / 用户 / 内容 / 社区 / 插件 / 系统 / 维护）。
- 二级导航：当前模块下的功能域分组（不是页面平铺）。
- 三级导航：具体功能页面入口。
- 页内 Tab：仅用于当前页面的数据状态筛选或内容分组，不属于左侧导航；建议同步到 URL query（如 `?status=enabled`），但不改变左侧菜单选中状态。
- 面包屑：用于展示当前位置（一级模块 / 二级功能域 / 三级功能页 / 当前页面）。

导航配置入口：`web/admin-app/src/router/adminNav.js`。

## 后续建议

- 将首页模块顺序和显隐从页面内部常量继续抽象为站点配置。
- 将站点导航从静态默认值逐步切换到“配置优先、默认值兜底”。
- 补齐更正式的基础组件目录和命名规范。
- 增加主题切换测试清单，确保更换 token 后页面层级仍稳定。
