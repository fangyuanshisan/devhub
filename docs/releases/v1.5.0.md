# DevHub v1.5.0 Release Notes

定位：插件包治理收口版。

当前 `VERSION` 为 `v1.5.0`；本页记录 v1.5.0 的真实落地能力、限制和验收结果，避免把后续规划写成已完成。

## v1.5.0-P0-01：插件包规范草案与本地插件包 dry-run 导入（已落地）

本轮目标：只做“本地插件包目录规范 + 安全扫描 + manifest 校验 + dry-run 预览”，不安装、不执行、不动态加载。

已完成：

- 新增本地插件包规范文档：`docs/PLUGIN_PACKAGE.md`。
- 后端新增本地插件包 dry-run 预览接口：
  - `POST /api/v1/admin/plugins/packages/dry-run`
  - 只允许读取白名单目录：`examples/plugins/`、`plugins-local/`、`storage/plugins/packages/`、`.devhub/plugins/`
  - 支持文件扫描（allowed/unknown/dangerous）、大小限制、危险文件阻断（blocked）
  - 复用现有 manifest validate / dry-run 逻辑产出安装预览
- 后台插件安装升级页新增“本地插件包 dry-run”区域（只读诊断与预览，不提供正式安装按钮）。
- 新增安全示例插件包：`examples/plugins/demo_notice/`。

明确边界（仍不支持）：

- 不支持 zip 上传、不支持远程市场、不支持远程下载、不支持在线更新。
- 不支持正式安装本地插件包（只 dry-run）。
- 不执行第三方本地代码、不执行外部 raw SQL。
- 不动态加载前端资产、不做 Go 动态加载、不做 JS/WASM/Lua 沙箱。
- P0 阶段不做插件包签名验签；签名/可信来源草案见 `v1.5.0-P2-09`（仍不做证书链/远程可信源/市场）。

新增错误码（用于包路径与 manifest 相关错误）：

- `plugin_package_path_invalid`
- `plugin_package_not_found`
- `plugin_package_manifest_missing`
- `plugin_package_manifest_invalid`
- `plugin_package_dangerous_file`
- `plugin_package_file_too_large`
- `plugin_package_too_large`
- `plugin_package_too_many_files`
- `plugin_package_unknown_files`
- `plugin_package_dry_run_blocked`

验收命令与结果：见 `docs/TESTING.md` 的 v1.5.0 对应条目（以实际执行记录为准）。

## v1.5.0-P1-06：插件敏感配置加密存储（进行中）

本轮目标：为插件配置中的 token/secret/password 等敏感字段提供后端加密存储能力，避免明文/密文泄露到 API、审计、diff、版本历史与回滚预览。

当前已落地（以仓库实现为准）：

- 敏感字段识别：优先 `config_schema` 的 `x-sensitive/writeOnly/format=password`，并以字段名/路径关键词作为兜底（支持嵌套 path）。
- AES-256-GCM 加密存储：敏感字段入库前加密为 `enc:v1:<nonce_b64>:<cipher_b64>`（每字段独立 nonce，不重复加密已加密值）。
- 占位符保留原值：UI/请求中敏感字段提交 `[ENCRYPTED]` 或 `******` 时保留已存密文；提交空字符串表示清空。
- API/审计/版本历史/diff：继续只返回脱敏视图，不返回明文或 `enc:v1:` 密文。

明确边界（仍不支持）：

- 不集成 KMS/Vault，不做密钥轮换/多密钥版本解密。
- 不做历史全量明文迁移任务（仅做向前兼容与展示脱敏，后续可专项推进）。

## v1.5.0-P2-09：插件包签名与可信来源草案（已落地）

本轮目标：为未来插件市场/可信分发打基础，补齐插件包签名元数据、可信来源模型与签名校验 dry-run，并将签名状态纳入 `risk_report` 与后台展示；不引入远程市场/自动下载/证书链验证/公钥服务器。

已完成：

- 插件包新增可选文件（不强制）：
  - `publisher.json`：发布者声明（不作为信任来源）。
  - `signature.json`：签名声明（当前支持 ed25519）。
- 本地可信来源配置（唯一信任来源）：
  - `storage/plugins/trusted_publishers.json`（`publisher_id + public_key_id` 匹配后标记 `trusted/blocked/revoked/unknown`）。
- dry-run/仓库扫描/详情接口新增 `signature` 字段摘要：
  - `trust_status=trusted|unknown|blocked|revoked|unsigned`
  - `verification_status=verified|failed|missing|unsupported|structural_only`
- 签名校验规则（当前实现）：
  - 签名对象：`sha256(raw_bytes_of_checksums.json)`，使用 `ed25519.Verify` 校验。
  - `signature.json` / `publisher.json` 非法 JSON、算法不支持、验签失败、publisher blocked/revoked：dry-run `blocked`。
  - 未签名/未知发布者：不阻断，但会提升风险等级并给出修复建议。
- 风险报告联动：
  - `risk_report` 会包含签名/发布者相关风险项（并给出 suggestion）。
- 后台展示：
  - 插件安装升级页“本地插件包 dry-run / 本地插件仓库 / 详情 / 安装确认弹窗”展示签名状态与可信来源状态。
- 示例与 fixtures：
  - `examples/plugins/demo_signed_notice/`（trusted + verified 示例）
  - `examples/plugins/security-fixtures/*`（仅用于测试/演示）
- 新增后台 Playwright：
  - `web/admin-app/tests/e2e/plugin-package-signature.spec.js`

明确边界（仍不支持）：

- 不做远程插件市场、不做远程下载、不做在线更新。
- 不做 zip 上传、不做动态加载 Go 代码、不执行第三方代码/SQL。
- 不做证书链验证/公钥服务器/可信发布者平台/密钥轮换。

验收命令与结果：见 `docs/TESTING.md`（以实际执行记录为准）。

## v1.5.0-P1-07：插件安装 / 升级审批流（已落地：install/upgrade）

本轮目标：为本地插件包安装与插件升级引入最小审批流。普通管理员提交申请，审批人通过后执行；执行时仍会重新 dry-run 校验，审批不等于绕过后端强校验。

已完成：

- 新增审批数据模型：`plugin_approval_requests`（记录 action/status、dry-run/risk 快照、审批与执行信息）。
- 新增后台审批 API：
  - `POST /api/v1/admin/plugins/approvals`
  - `GET /api/v1/admin/plugins/approvals`
  - `GET /api/v1/admin/plugins/approvals/:id`
  - `POST /api/v1/admin/plugins/approvals/:id/approve|reject|cancel|execute`
- 审批执行规则：执行前强制重新运行 package scan/checksum/risk/依赖/兼容（install）或 upgrade dry-run（upgrade）；若变为 blocked 则执行失败并记录错误码。
- 权限：新增 `plugin.approve` 用于审批/执行；本地插件包安装与插件升级的“直接执行”接口收敛为 `plugin.approve`（普通管理员走审批申请）。
- 后台安装升级页支持从本地插件仓库提交“安装审批”；新增“审批中心”页面用于列表/详情/通过/拒绝/撤销/执行。
- 新增后台 Playwright：`web/admin-app/tests/e2e/plugin-approvals.spec.js`。

明确边界（仍不支持）：

- 不做多级审批、不做通知推送、不做工作流引擎。
- 本轮审批范围只覆盖 install/upgrade；enable/rollback 审批留到后续版本评估。

验收命令与结果：见 `docs/TESTING.md`（以实际执行记录为准）。

## v1.5.0-P2-10：已安装插件导出为本地插件包（已落地：声明型导出）

本轮目标：支持将已安装的声明型插件导出为 DevHub 本地插件包目录，便于备份、迁移、二次分发和未来插件仓库治理。导出只包含声明、文档和示例配置，不导出敏感配置、用户数据、运行时代码或外部 SQL。

已完成：

- 后端新增导出 API：
  - `POST /api/v1/admin/plugins/:code/export/dry-run`：导出预览，不写文件。
  - `POST /api/v1/admin/plugins/:code/export`：正式导出到 `storage/plugins/exports/`，生成文件后自动执行 package dry-run 自检。
- 导出文件：
  - 必选：`manifest.json`、`README.md`、`config.example.json`、`checksums.json`。
  - 可选：`docs/usage.md`、`migrations/exported_migrations.json`、`publisher.json`、`signature.json` 草案结构。
- 安全规则：
  - `config.example.json` 只使用 `default_config` 或 `config_schema` 生成示例；敏感字段统一写为 `REPLACE_ME`。
  - 不导出当前全局配置真实值、子站配置真实值或 `enc:v1:` 密文。
  - 不导出用户数据、帖子/评论/通知、审计原始明细、Hook 历史、搜索索引、运行时代码、动态前端资产、外部 SQL、私钥或 token/secret/password。
- 后台插件详情 Overview 新增“导出本地插件包”面板：
  - 支持 dry-run、文件列表、安全检查、正式导出确认、输出目录展示和复制路径。
  - 不显示 zip 下载、远程发布或插件市场发布入口。
- 后端测试：
  - `internal/service/plugin_export_test.go`
- 后台 E2E：
  - `web/admin-app/tests/e2e/plugin-package-export.spec.js`

明确边界（仍不支持）：

- 不做 zip 打包下载。
- 不做远程上传、插件市场发布或市场审核。
- 不做自动签名发布；`signature.json` 仍是草案结构。
- 不做跨环境自动导入、在线更新、动态加载或第三方代码执行。
