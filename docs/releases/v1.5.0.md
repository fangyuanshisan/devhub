# DevHub v1.5.0 Release Notes（进行中）

定位：插件分发能力预研阶段（本地插件包规范草案与 dry-run 导入预览）。

当前 `VERSION` 仍为 `v1.4.0`；本页用于记录 v1.5.0 规划阶段的真实落地能力与边界，避免把后续规划写成已完成。

## v1.5.0-P0-01：插件包规范草案与本地插件包 dry-run 导入（已落地）

本轮目标：只做“本地插件包目录规范 + 安全扫描 + manifest 校验 + dry-run 预览”，不安装、不执行、不动态加载。

已完成：

- 新增本地插件包规范文档：`docs/PLUGIN_PACKAGE.md`。
- 后端新增本地插件包 dry-run 预览接口：
  - `POST /api/v1/admin/plugins/packages/dry-run`
  - 只允许读取白名单目录：`examples/plugins/`、`plugins-local/`、`storage/plugins/packages/`、`.devhub/plugins/`
  - 支持文件扫描（allowed/unknown/dangerous）、大小限制、危险文件阻断（blocked）
  - 复用现有 manifest validate / dry-run 逻辑产出安装预览
- 后台插件安装升级页新增“本地插件包 dry-run”区域（只读诊断与预览，不提供正式安装按钮）。
- 新增安全示例插件包：`examples/plugins/demo_notice/`。

明确边界（仍不支持）：

- 不支持 zip 上传、不支持远程市场、不支持远程下载、不支持在线更新。
- 不支持正式安装本地插件包（只 dry-run）。
- 不执行第三方本地代码、不执行外部 raw SQL。
- 不动态加载前端资产、不做 Go 动态加载、不做 JS/WASM/Lua 沙箱。
- 不做插件签名与 checksum 强校验（后续版本再做）。

新增错误码（用于包路径与 manifest 相关错误）：

- `plugin_package_path_invalid`
- `plugin_package_not_found`
- `plugin_package_manifest_missing`
- `plugin_package_manifest_invalid`
- `plugin_package_dangerous_file`
- `plugin_package_file_too_large`
- `plugin_package_too_large`
- `plugin_package_too_many_files`
- `plugin_package_unknown_files`
- `plugin_package_dry_run_blocked`

验收命令与结果：见 `docs/TESTING.md` 的 v1.5.0 对应条目（以实际执行记录为准）。

## v1.5.0-P0-02：插件包安全校验、checksum 与导入风险报告（已落地）

本轮目标：在 P0-01 的基础上补齐 **checksums.json（sha256）校验**、危险规则强化与 **risk_report 风险报告**；仍只做 dry-run，不安装、不执行、不动态加载。

已完成：

- 后端增强 `POST /api/v1/admin/plugins/packages/dry-run`：
  - `checksums.json` 解析与 sha256 校验（缺失 warning；非法/不匹配 blocked；未覆盖文件当前 warning）。
  - 强化危险规则：软/硬链接（可检测）、隐藏目录、可执行权限文件、dist/build、扩展名黑名单等。
  - 返回 `checksum` 与 `risk_report`（`low|medium|high|blocked`），并补充 `blocked_reasons` 供 UI 逐项展示。
- 后台“本地插件包 dry-run”区域增强展示：
  - checksum 状态、mismatched/extra 列表
  - 风险等级与风险项明细（code/message/suggestion）
- 示例插件包补齐 `checksums.json`：`examples/plugins/demo_notice/checksums.json`。
- 新增安全/危险 fixtures（仅用于测试/演示，不作为正式示例包）：
  - `examples/plugins/security-fixtures/no_checksums`
  - `examples/plugins/security-fixtures/checksum_mismatch`
  - `examples/plugins/security-fixtures/dangerous_shell`
- 新增后台 Playwright：
  - `web/admin-app/tests/e2e/plugin-package-security.spec.js`

明确边界（仍不支持）：

- 不支持 zip 上传、不支持远程市场、不支持远程下载、不支持在线更新。
- 不支持正式安装本地插件包（只 dry-run）。
- 不执行第三方本地代码、不执行外部 raw SQL。
- 不动态加载前端资产、不做 Go 动态加载、不做 JS/WASM/Lua 沙箱。
- 不做插件签名与可信发布者体系（后续版本再做）。

验收命令与结果：见 `docs/TESTING.md`（以实际执行记录为准）。

## v1.5.0-P0-04：本地插件包安装闭环（已落地）

本轮目标：在 P0-01~P0-03 的 dry-run/风险治理基础上，补齐“从本地插件包安装声明型插件”的最小闭环；仍不执行第三方代码/SQL，不动态加载前端资产。

已完成：

- 后端新增本地插件包安装接口：
  - `POST /api/v1/admin/plugins/packages/install`
  - 服务端会在安装前强制复跑 package dry-run（scan/checksum/risk/manifest validate/install preview），不信任前端缓存结果。
  - 阻断：blocked 风险/危险文件/checksum 不匹配/manifest 非法/required 依赖缺失/Core 不兼容/同 code 已安装等。
  - 安装成功后插件状态固定为 `disabled`，`source_type=local_package`（不自动启用）。
- 后台“本地插件仓库”列表增加安装动作：
  - 仅 `status=ok|warning` 且未 blocked 的包显示可点击安装
  - 安装前弹窗展示 risk/checksum/dry-run 边界提示与确认项
  - 安装成功后可在插件列表看到新插件（disabled）
- 新增后端测试：`internal/service/plugin_package_install_test.go`
- 新增后台 Playwright：
  - `web/admin-app/tests/e2e/plugin-package-install.spec.js`

明确边界（仍不支持）：

- 不支持 zip 上传、不支持远程市场/下载/在线更新。
- 不自动安装依赖、不做正式安装审批流。
- 不执行第三方本地代码、不执行外部 raw SQL。
- 不动态加载前端资产、不做 Go 动态加载、不做脚本沙箱。
- 不做插件签名与可信发布者体系（后续版本再做）。

验收命令与结果：见 `docs/TESTING.md`（以实际执行记录为准）。

## v1.5.0-P0-03：本地插件仓库目录与插件包扫描（已落地）

本轮目标：建立受控的“本地插件仓库目录”，支持扫描多个插件包并展示 discovered packages（列表/筛选/详情/dry-run），仍只做扫描/校验/展示与 dry-run，不安装、不执行、不动态加载。

已完成：

- 后端新增本地插件仓库扫描接口：
  - `GET /api/v1/admin/plugins/packages`（支持 root/status/keyword/risk_level/checksum_status/manifest_valid/page/page_size）
  - `GET /api/v1/admin/plugins/packages/detail?path=...`（复用 dry-run 详情视图；blocked/invalid 也可查看原因）
- 后台安装升级页新增“本地插件仓库”视图：
  - 扫描/刷新
  - discovered packages 列表（status/risk/checksum/files/size）
  - 详情抽屉（风险/校验/dry-run 预览）
- 新增仓库扫描测试 fixtures：`plugins-local/repository-fixtures/`（仅测试/演示用；不代表正式可分发包）。
- 新增后台 Playwright：
  - `web/admin-app/tests/e2e/plugin-package-repository.spec.js`

明确边界（仍不支持）：

- 不支持正式安装本地插件包（只扫描/详情/dry-run）。
- 不支持 zip 上传、不支持远程市场/下载/在线更新。
- 不执行第三方本地代码、不执行外部 raw SQL。
- 不动态加载前端资产、不做 Go 动态加载、不做脚本沙箱、不做签名与可信发布者体系。

验收命令与结果：见 `docs/TESTING.md`（以实际执行记录为准）。
