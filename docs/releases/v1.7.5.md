# v1.7.5：Webhook 重试队列与熔断机制增强版

本轮任务：在 `v1.7.4` 的 Webhook non_blocking delivery 基础治理能力上，补齐 **失败重试队列** 与 **circuit breaker 熔断机制**，并提供最小后台治理入口与审计闭环。

> 说明：本轮为实现任务，包含后端与后台管理端改动。  
> 仍然不执行第三方插件代码，不做动态加载，不做 blocking Hook。

## 范围

已实现：

- Webhook delivery 状态扩展：`retry_scheduled` / `retry_exhausted` / `circuit_open`
- `next_retry_at` 调度字段、`attempt/max_attempts`、`retry_reason`
- 失败重试扫描：`retry-due`（轻量队列：DB 扫描 + limit）
- Circuit breaker（维度：`plugin_code + target_url`）：`closed/open/half_open`
- `half_open` probe 逻辑（到达 `next_probe_at` 允许探测一次）
- 管理员手动恢复/打开熔断
- Admin API：delivery 列表/详情/手动重试/批量重试到期、熔断列表/详情/close/open
- 后台最小 UI：Plugins → 运行时治理 → Webhook 治理（Deliveries/Circuit Breakers）
- 审计动作补齐：重试/熔断相关 action

未实现 / 明确不做：

- blocking Hook
- 插件回调 Core API token / scopes
- Secret 轮换与 HMAC 签名发送端/接收端验签（建议 v1.7.6）
- 外部队列系统（Redis/Kafka/RabbitMQ）
- 第三方代码执行 / Go plugin 动态加载

## 关键规则

- **仅 non_blocking**：失败不会阻断 Core 主流程。
- **重试策略（默认）**：
  - 第 2 次：+1 分钟
  - 第 3 次：+5 分钟
  - 第 4 次：+15 分钟
  - 第 5 次：+1 小时
  - 超过 `max_attempts` → `retry_exhausted`
- **HTTP 状态策略**：
  - `2xx`：成功
  - `4xx`：默认不重试
  - `408/timeout`、`5xx`：可重试
  - `429`：可重试，优先 `Retry-After`
- **熔断策略（默认）**：
  - 连续失败 `>= 5` → `open`，并设置 `next_probe_at = now + 10min`
  - `open` 状态下：投递进入 `circuit_open`（不继续打爆）
  - 到达 `next_probe_at`：允许一次 `half_open` 探测；成功关闭，失败重新打开

## 运维与验收提示

- Webhook 治理入口为后台管理端 `/admin-next` 的 **插件 → 运行时治理 → Webhook 治理**。
- 生产环境建议后续补齐 Webhook 签名鉴权与 secret 轮换（v1.7.6）。
