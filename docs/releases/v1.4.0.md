# DevHub v1.4.0 Release Notes

定位：插件内容治理增强版。

当前 `VERSION` 已切到 `v1.4.0`。本页记录本轮插件内容治理增强的实现范围、验收结果和保留边界。

## 已完成

- `GET /api/v1/admin/posts` 支持 `plugin_code` 参数，并按 `plugin_code + content_type` 精确过滤插件内容。
- 后台帖子行返回 `plugin_code` 和 `content_type`，MemoryStore / MySQLStore 对历史缺失字段做防御性归一。
- `PluginContent` 头部展示插件名、插件编码、插件状态、健康状态和内容类型数量。
- disabled / archived 插件可进入历史内容治理页，并明确提示不能新建、历史内容仍可治理。
- `PluginContent` 批量治理支持隐藏 / 恢复、审核通过 / 拒绝、置顶 / 取消置顶、加精 / 取消加精。
- 批量治理后展示成功 / 失败明细，并保留结构化插件审计。
- 审计跳转带上 `plugin_code`、`content_type`、`action`，详情抽屉提供最近治理审计入口。
- 最小 E2E 覆盖归档插件历史治理、精确过滤、批量隐藏 / 恢复、批量置顶 / 取消置顶、批量加精 / 取消加精、批量拒绝 / 审核通过链路。
- `config_schema` 自动表单增强：全局插件配置与子站插件配置统一使用 `PluginConfigEditor`（代码组件名 `PluginConfigEditor`），支持“表单模式 + JSON 高级模式”、字段标题/说明、默认值展示、必填提示、enum 下拉、boolean switch、number/integer 输入限制、简单对象/数组编辑、字段分组与保存前配置差异预览；敏感字段在表单与 diff/预览中默认脱敏并可切换显示。
- Hook 排障页（插件详情 Hooks Tab）：展示 Hook 统计（执行/成功/失败/失败率/平均耗时/最近执行/最近失败/最近错误、blocking/non-blocking）与最近执行记录，并提供执行记录查询/详情抽屉与审计跳转。
- 插件 SDK 文档与生成模板：新增 `docs/PLUGIN_SDK.md`、`docs/PLUGIN_TEMPLATE.md`、`docs/examples/plugin-manifest-example.json`、`examples/plugins/demo_links/` 和 `go run ./cmd/devhub plugin:new ...`；模板只生成声明、配置、文档和示例，并复用现有 ManifestValidator / config_schema 校验。

## v1.4.0-P1-07：插件依赖检查与版本兼容矩阵增强

本轮新增统一依赖治理能力：`dependencies` 支持对象声明（`code`、`version`、`required`、`reason`）并兼容旧字符串数组；依赖检查覆盖缺失、未启用、归档、迁移失败、配置无效、版本不匹配、自依赖和循环依赖。required 不满足会阻断 validate / dry-run / install / upgrade dry-run / upgrade / enable；optional 缺失仅 warning；optional 循环当前仍阻断。

Core 兼容矩阵现在返回 `core_version`、`min_core_version`、`compatible_core_version`、`status` 和 `messages`。`min_core_version` 缺失为 warning，高于当前 Core 或 `compatible_core_version` 不满足时按 incompatible 阻断。当前 Core 版本来自项目 `VERSION`。

后台 `/admin-next/plugins` 安装向导、升级向导和插件详情 Dependencies 区域展示依赖总览、required / optional、当前版本、要求版本、状态、阻断原因、Core 兼容状态和升级依赖 diff；不提供自动安装依赖、远程下载、插件市场推荐或依赖图大屏。

新增 / 调整测试：

- 后端：`internal/plugins/version_compat_test.go`、`internal/service/plugin_dependencies_test.go`。
- E2E：`web/admin-app/tests/e2e/plugin-dependencies.spec.js`。

已执行：

- `go test ./internal/plugins ./internal/plugins/scaffold ./internal/service ./internal/transport/httpapi`：通过。
- `docker compose run --rm admin-e2e npm run build`：通过。
- `docker compose run --rm admin-e2e npm run test:e2e -- tests/e2e/plugin-dependencies.spec.js`：最终通过，`2 passed`。

仍不支持：自动安装依赖、插件市场、远程安装、动态加载、脚本沙箱、第三方代码执行、复杂 npm 风格版本约束、插件签名、migration down、hard uninstall、配置回滚。

## v1.4.0-P1-10：插件治理错误码统一与 Readiness 诊断（已落地，仍有边界）

本轮目标是让后台在“为什么不能启用 / 升级 / 安装 / 归档 / 配置保存”这类场景下，能展示统一错误码、可操作提示（suggestion）与关键细节（details），并提供轻量 Readiness Check 接口用于诊断展示。

当前实现（本仓库真实状态）：

- 后端：插件治理相关接口在错误响应中新增 `code/message/details/suggestion`，并保留旧字段 `error` 兼容旧前端。
- 后端：新增 `GET /api/v1/admin/plugins/:code/readiness?action=enable`，返回 `pass/warning/blocked` 与逐项 checks（依赖、Core 兼容、config_schema、迁移等）。
- 后端：插件治理相关的权限拒绝在插件路由下返回结构化错误码（保留 legacy `error`），并在 `details.permission_code` 中提示缺少的权限点。
- 后端：插件治理失败审计（install/upgrade/archive/restore/migration 等）在 `metadata_json` 中补充 `error_code/details/suggestion`，用于后台高亮和定位。
- 后台：统一错误 toast 文案展示 `[code] message 建议：suggestion`，避免只提示“操作失败”。
- 后台：插件详情新增“操作诊断”Tab，展示 readiness checks 明细，并支持从依赖项跳转到依赖插件详情。
- 后台：插件详情“权限”Tab 增强缺失/高危高亮，支持按权限码搜索、只看缺失权限、只看高危权限，并可查看权限引用关系（menus/routes/content types）。

未覆盖 / 待补齐：

- action 维度 readiness（install/upgrade/archive/restore/configure）目前以 enable 为主，后续按 P1-10 任务清单补齐。
- 更完整的权限矩阵增强（来源插件/适用范围细化、按钮/API 影响映射、引用关系图谱）仍需继续对齐实现。
- 审计日志的依赖/权限/版本/Hook/config 错误高亮规则仍需继续扩展到更多 action，并补充跨页面跳转入口。

## v1.4.0-P1-11：插件前台入口与菜单可见性治理（已落地，仍有边界）

本轮目标是收口前台“入口是否展示 / 是否可创建 / 为什么不可见”这一类治理体验，避免插件 disabled/archived/dependency_missing/config_invalid/migration_failed 时继续暴露新建入口，同时保证历史内容与 SEO 不退化。

当前实现（本仓库真实状态）：

- Manifest：`MenuDefinition` 新增前台入口治理字段（`route/location/content_type/require_login/require_community_enabled/require_category_binding/visible_when/order/badge`），旧 manifest 缺字段保持兼容（只影响入口展示，不绕过后端权限）。
- 后端：新增/整理前台入口解析接口：
  - `GET /api/v1/navigation`
  - `GET /api/v1/communities/:slug/navigation`
  - `GET /api/v1/communities/:slug/create-options`
- 后端：新增后台诊断接口 `GET /api/v1/admin/plugins/:code/menus/preview`（仅 admin token + `plugin.read`），用于解释“为什么该插件前台菜单不可见”。
- 内置系统插件：`qa/docs/wiki/projects/jobs/ai_works` 增加 `Area=frontend` 的 `community_nav` 菜单声明，使前台导航可根据后端解析结果统一隐藏 disabled/archived 等异常状态下的入口。
- 前台：发布页通过 `create-options` API 过滤可创建内容类型；当后端接口不可用时回退到老的 `community plugins` 口径（兼容旧后端）。
- 后台：插件详情 “菜单”Tab 增强“前台入口预览”面板，可按 `community_slug/category_id` 预览可见性与原因（默认按管理员视角）。

新增 / 调整测试：

- 后端：`internal/transport/httpapi/plugin_navigation_test.go`
- 后台 E2E：`web/admin-app/tests/e2e/plugin-navigation-admin.spec.js`
- 前台 E2E：`web/frontend-app/tests/e2e/plugin-navigation.spec.js`

仍保留边界：

- 不做插件市场、远程安装、动态加载、脚本沙箱、第三方代码执行。
- 导航入口目前以“可见性治理”为主，不做复杂个性化菜单系统或拖拽排序后台。

## v1.4.0-P1-13：插件后台信息架构与按功能分页优化（已落地）

本轮目标是把后台“系统插件”从聚合大页整理为“一级入口 + 二级按功能分页”，让管理员能按功能进入对应页面，不再在一个超大页面里找功能；不新增插件底层能力，不改变既有 API/权限语义。

落地内容（后台路由）：

- `/admin-next/plugins`：重定向到 `/admin-next/plugins/overview`。
- `/admin-next/plugins/governance`：重定向到 `/admin-next/plugins/overview`（旧路由兼容不 404）。
- `/admin-next/plugins/overview`：插件概览（全局 stats、最近异常、快捷入口）。
- `/admin-next/plugins/list`：插件列表（筛选/批量归档恢复/详情抽屉入口）。
- `/admin-next/plugins/content`：内容治理入口聚合（卡片跳转到旧路由 `/admin-next/qa|docs|wiki|projects|jobs|ai-works`）。
- `/admin-next/plugins/install`：安装升级入口（validate/dry-run/install/upgrade preview/upgrade）。
- `/admin-next/plugins/config`：配置中心入口聚合（跳转到插件详情配置 Tab 或子站插件配置）。
- `/admin-next/plugins/dependencies`：依赖兼容聚合（跳插件详情依赖 Tab）。
- `/admin-next/plugins/hooks`：Hook 排障聚合（跳插件详情 Hook Tab）。
- `/admin-next/plugins/events`：事件通知入口（只展示边界与说明，不提供未实现假按钮）。
- `/admin-next/plugins/search-index`：搜索索引入口（只展示边界与说明，不提供未实现假按钮）。
- `/admin-next/plugins/navigation`：前台入口聚合（跳插件详情 Menus Tab）。
- `/admin-next/plugins/permissions`：权限矩阵聚合（跳插件详情 Permissions Tab）。
- `/admin-next/plugins/audit`：审计日志入口聚合（跳转全局审计并带 query）。
- `/admin-next/plugins/developer`：开发者工具（文档/命令入口；不提供后台生成文件按钮）。

交互与兼容：

- 二级导航按“插件运营 / 安装与治理 / 运行排障 / 开发者”分组展示，数量不限制并支持滚动。
- `PluginContent` 的“返回插件中心”入口调整为返回 `/admin-next/plugins/content`（内容治理聚合页）。
- E2E 新增 `web/admin-app/tests/e2e/plugin-pages-navigation.spec.js`，覆盖二级分页导航与旧路由兼容。
