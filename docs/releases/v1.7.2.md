## 运行模型结论

### Core 内置插件

- 适用于 `qa`、`docs`、`wiki`、`projects`、`jobs`、`ai_works` 等官方基础能力。
- 随 DevHub 主仓库编译发布，运行在 DevHub 进程内。
- 可使用 Core 内部接口，但必须受权限、配置、审计、生命周期和 HookBus 约束。

### 外部 HTTP 服务插件

- 第三方插件后端作为独立 HTTP 服务运行。
- DevHub 不加载插件 Go 代码，不执行包内脚本，不执行第三方二进制。
- DevHub 通过签名请求或 token 调用插件服务。
- 插件服务通过受控 Core API 调用 DevHub 能力。
- 插件服务失败不能拖垮 Core。
- 这是中期推荐的第三方后端插件运行方式。

### 前端 iframe / sandbox 插件

- 第三方插件前端页面通过 iframe 或 sandbox 容器挂载。
- DevHub 不直接执行不可信 JS。
- 插件与 DevHub 通过 `postMessage` 或受控 SDK 通信。
- 插件只能访问授权上下文，不能绕过权限访问后台 API。
