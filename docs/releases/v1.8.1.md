# v1.8.1：官方公告插件前端挂载最小实现版

更新时间：2026-05-18

本版本在 v1.8.0“官方插件前端挂载模型与 iframe / sandbox 容器设计”基础上，落地 `official_announcement` 作为 **内置官方插件** 的前端挂载最小闭环。

本轮完成后，项目文档为长期状态来源；聊天回复仅作为摘要。

本轮执行记录：

- 本轮实现官方公告插件前端挂载最小闭环，涉及 Go 后端、前台与后台源码改动。
- 本轮未执行第三方不可信代码、未加载远程 iframe URL、未引入动态远程脚本。

## 1. 本轮目标

1. 将 `official_announcement` 作为内置官方插件加入 `internal/plugins`。
2. 在前台首页挂载公告展示区（Host + iframe）。
3. 在后台插件详情页新增“公告预览”Tab（Host + iframe）。
4. iframe 默认启用 `sandbox="allow-scripts"`，不允许远程 URL。
5. 通过 postMessage 实现最小 handshake，并以 Host API 完成 `config.read` / `audit.write` 的受控闭环。

## 2. 已实现（真实落地）

### 2.1 内置官方插件

- 新增内置插件：`official_announcement`。
- 插件配置 schema：`enabled/message/link_text/link_url/dismissible`（仅站内链接，禁止 `javascript:` / `data:`）。

### 2.2 Iframe 页面（内置）

- 新增 iframe 页面路由：`GET /plugins/official-announcement/iframe`。
- 该页面由 DevHub 仓库内置提供，不允许管理员配置任意远程 URL。
- iframe 不持有任何 Core token / callback token / webhook secret。

### 2.3 Host API（浏览器安全）

新增官方公告插件 Host 专用 API：

- `GET /api/v1/plugins/official-announcement/context`
  - 返回 browser-safe context + 公开配置（不返回 callback token / webhook secret）。
  - 支持 `area=frontend|admin`，`admin` 场景要求后台管理员身份与 `plugin.read`/`plugin.manage` 权限。
- `POST /api/v1/plugins/official-announcement/audit-events`
  - 写入 `official_announcement.*` 前缀的审计事件（不允许伪造其他插件/核心审计）。
  - v1.8.1-S2 补充：支持 `community_slug` 字段用于子站页场景的 gating 校验（子站插件 disabled 时拒绝写入）。

### 2.4 前台挂载（最小闭环）

- 前台首页：通过 Host API 获取配置，满足 `enabled && message 非空` 时挂载 iframe。
- 子站页（`/c/:slug`）：通过 Host API（携带 `community_slug`）获取配置，并在子站插件启用时挂载 iframe。
- iframe 与 Host 通过 postMessage：`ready -> context -> config.read -> config.result -> audit.write`。
- 失败不影响首页主内容与 SEO。

### 2.5 后台挂载（最小闭环）

- 后台插件详情 Drawer：当 `plugin.code === official_announcement` 时显示“公告预览”Tab。
- Tab 内使用 Host API `area=admin` 拉取配置，并挂载 iframe 预览。
- 权限不足时显示“权限不足”，且后端 API 同样拒绝。

## 4. 安全边界（口径收口）

1. 不向浏览器暴露 callback token / webhook secret。
2. iframe 仅允许仓库内置页面路由，不支持配置任意远程 URL。
3. postMessage 仅作为 Host 与 iframe 的通信机制；真正的权限校验在后端完成。
