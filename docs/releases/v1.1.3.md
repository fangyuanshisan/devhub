# DevHub v1.1.3 - 独立版主工作台 MVP

[返回文档大纲](../README.md)

发布日期：2026-05-09

## 版本定位

DevHub v1.1.3 是“独立版主工作台 MVP”。本版本为子站版主新增轻量独立入口，让版主不必进入完整 admin-next 后台，也能处理自己负责子站的举报、内容、评论和审计记录。

## 权限模型

- 版主工作台使用前台 `users` 登录态。
- 版主权限来自 `community_moderators.user_id + community_id + status=1`。
- `admin_users` 仍用于 `/admin-next` 后台管理，不作为版主工作台身份。
- 后端对所有列表和单项治理都校验 `community_id`，跨子站访问返回 403。

## 页面范围

- `/moderator`：工作台概览。
- `/moderator/reports`：举报处理。
- `/moderator/topics`：内容治理。
- `/moderator/comments`：评论治理。
- `/moderator/audit-logs`：子站审计日志。

普通用户进入工作台会看到无权限提示；多子站版主可在页面中切换自己负责的子站。

## API 范围

新增 `/api/v1/moderator/*` 专用 API：

- `GET /api/v1/moderator/communities`
- `GET /api/v1/moderator/dashboard`
- `GET /api/v1/moderator/reports`
- `POST /api/v1/moderator/reports/:id/handle`
- `GET /api/v1/moderator/topics`
- `POST /api/v1/moderator/topics/:id/feature`
- `POST /api/v1/moderator/topics/:id/unfeature`
- `POST /api/v1/moderator/topics/:id/pin`
- `POST /api/v1/moderator/topics/:id/unpin`
- `POST /api/v1/moderator/topics/:id/hide`
- `POST /api/v1/moderator/topics/:id/restore`
- `POST /api/v1/moderator/topics/:id/lock-comments`
- `POST /api/v1/moderator/topics/:id/unlock-comments`
- `GET /api/v1/moderator/comments`
- `POST /api/v1/moderator/comments/:id/hide`
- `POST /api/v1/moderator/comments/:id/restore`
- `GET /api/v1/moderator/audit-logs`

这些接口复用现有 reports、topics、comments 治理能力和 `admin_logs`，但使用独立鉴权入口。

## 审计日志

版主工作台治理操作写入 `admin_logs`：

- `actor_type=moderator`
- `actor_id=users.id`
- `actor_user_id=users.id`
- `community_id` 对应目标所属子站
- `action` 使用 `handle_report`、`feature_topic`、`hide_topic`、`hide_comment` 等稳定动作名

版主只能查看自己负责子站的审计记录。

## 不做内容

- 不做复杂 RBAC。
- 不做权限点矩阵编辑器。
- 不做 OAuth / SSO。
- 不拆分 refresh token 表。
- 不做标签、推荐、声望、版主任期或绩效统计。
- 不允许版主管理后台人员、系统设置、版主分配或其他子站。
- 不改变 `/topics/:id` 和 `/c/:slug` 的 Go 动态 SEO HTML。

## 已知限制

- 版主工作台是 MVP，不替代完整 admin-next 后台。
- super_admin 仍建议使用 admin API 和 `/admin-next`。
- 复杂 RBAC、版主任期、绩效统计和更细的操作报表留到后续版本。
- 浏览器 Console 和端到端交互需要在后续 v1.1.3 验收任务中继续检查。
