# DevHub v1.1.4 - 前台登录态与权限入口修复版

[返回文档大纲](../README.md)

发布日期：2026-05-10

## 版本定位

DevHub v1.1.4 是“前台登录态与权限入口修复版”。本版本修复前台会员状态恢复、子站关注、“我的”类接口、版主工作台入口、后台子站入口重复和发布内容类型匹配问题。

本补丁已并入当前 v1.2.0 工作分支；不回退 `VERSION`。

## 完成内容

- 前台导航统一使用 `devhub_user_token` / `devhub_user_refresh_token`，并兼容旧 token key。
- `/api/v1/auth/me` 返回 `is_moderator` 和 `moderated_communities`。
- 普通前台会员不显示 `/admin-next` 总后台入口。
- 子站版主在前台用户菜单和 Go 动态页运行时看到 `/moderator` 入口。
- 子站关注请求携带前台 user token，未登录时提示登录。
- `/me/favorites`、`/me/follows`、`/me/activities`、`/notifications` 请求携带前台 user token。
- 发布页按 `type` / `content_type` 自动匹配当前子站板块。
- 后端 Topic 创建校验优先使用 `categories.content_type`，旧 `type` 兜底。
- 后台菜单只保留 `/admin-next/communities`，`/admin-next/sites` 作为隐藏兼容路由重定向。

## 不做内容

- 不重构完整认证系统。
- 不做 OAuth / SSO。
- 不做复杂 RBAC 或权限点矩阵。
- 不改变 `/topics/:id`、`/c/:slug`、`/tags/:tag` 的 Go 动态 SEO 主体。
- 不删除 `sites/posts` 兼容 API。

## 已知限制

- 总后台入口仍需要用户主动访问 `/admin-next` 并使用后台 admin 登录态。
- 版主工作台仍是 v1.1.3 MVP，不替代完整 admin-next 后台。
- 复杂身份绑定和更细粒度 RBAC 留到后续生产化版本。

## 后续测试重点

- 已登录用户在首页、子站页、Topic 详情页和用户中心页面均显示登录状态。
- 已登录用户可关注 / 取消关注子站。
- 普通会员不显示总后台入口。
- 版主显示 `/moderator` 入口。
- 发布 `question` 自动匹配问答板块。
- 后台菜单只显示一个子站管理入口。
