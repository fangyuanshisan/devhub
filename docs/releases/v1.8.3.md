## 版本定位

v1.8.3 定义为“后台插件治理页面稳定性与中文体验优化版”。

本轮只优化后台插件治理页面稳定性、页面结构、页内 Tab、详情抽屉分组、中文文案、空状态、危险操作提示和安全边界说明；不修改插件底层生命周期逻辑，不修改 Webhook 协议，不修改 Secret / Callback Token 安全模型。
当前版本仍保持 `v1.8.3` 为主线版本口径；`external_service` 仅完成 non-blocking delivery 子集，完整第三方运行模型后续再做。

### v1.8.3-S14：external_service non-blocking Webhook 投递闭环

- 声明型插件 Hook 声明新增 external_service 投递字段：`service_type=external_service`、`path`、`method`、`retry_enabled`、`max_attempts`、`enabled`；manifest 校验强制 external_service Hook 只能使用 `mode=non_blocking`，Hook `path` 必须是相对路径，第一版只支持 `POST`。
- HookBus 触发后会创建 `hook_executions(service_type=external_service)` 的 `pending` 记录，并在后台 goroutine 中异步投递 `POST {endpoint_url}{hook.path}`；主业务流程不等待远端响应，external_service 失败不会阻断内容发布 / 配置保存 / 用户操作主流程。
- 投递请求包含 `X-DevHub-Plugin-Code`、`X-DevHub-Hook-Name`、`X-DevHub-Execution-ID`、`X-DevHub-Event-ID`、`X-DevHub-Request-ID`、`X-DevHub-Idempotency-Key`、`X-DevHub-Timestamp`、`X-DevHub-Delivery-Mode: non_blocking`，payload 使用 schema_version=1 并携带资源、子站、actor 和事件追踪信息。
- 支持 `auth_type=none|bearer`、`timeout_ms`、`retry_enabled/max_attempts`、`failure_policy=ignore|warn|error|disable_hook`；timeout、5xx 和 429 可进入 `retry_scheduled`，超过次数进入 `retry_exhausted`，4xx / 401 / 403 / token 缺失默认不重试。
- 投递结果进入 `hook_executions`：记录 `pending/running/success/failed/timeout/retry_scheduled/retry_exhausted/skipped`、response_status、duration_ms、request_body_sha256、error_code、error_message、execution_id、event_id、idempotency_key、attempt、next_retry_at 和 health before/after。
- 失败会按阈值更新 external_service health warning / error，成功会恢复 healthy 并清零 failure_count；`disable_hook` 到 error 后后续投递记录 skipped，不自动禁用插件。
- 插件 disabled / archived / soft_uninstalled、external_service disabled、子站 disabled、endpoint 缺失或 token 缺失时不调用 endpoint，并写入 skipped / failed 执行记录和中文原因。
- 复用已有 `GET /api/v1/admin/plugins/:code/hooks/executions?service_type=external_service` 与后台详情抽屉 / 运行记录入口查看投递结果；本轮未新增手动 retry API。
- token 明文、Authorization Header、Webhook Secret、Callback Token、敏感请求体不进入接口响应、执行记录、日志或审计；本轮仍不执行第三方代码、不开放动态加载、不开放远程 iframe、不实现 blocking Hook。

### v1.8.3-S11：external_service Webhook 运行时预备

- 新增 external_service 运行时配置模型：`plugin_external_services` 保存 `plugin_code`、`service_type=external_service`、`endpoint_url`、`health_check_path`、`timeout_ms`、`failure_policy`、`auth_type`、`token_ref`、健康状态、最近检查时间和失败计数；MemoryStore / MySQLStore 均支持读写。
- 新增 Admin API：`GET /api/v1/admin/plugins/:code/external-service`、`PUT /api/v1/admin/plugins/:code/external-service`、`POST /api/v1/admin/plugins/:code/external-service/health-check`；`GET /plugins/:code/hooks/executions` 支持 `service_type=external_service` 筛选。
- endpoint 校验只允许 HTTPS，本地开发允许 `http://localhost`、`http://127.0.0.1`、`http://[::1]`；拒绝 `javascript:`、`data:`、`file:`、`ftp:`。`timeout_ms`、`failure_policy`、`auth_type` 均有白名单和默认值。
- Bearer token 使用插件配置 keyring 加密保存并生成 `token_ref`；接口、后台详情、审计、日志、`hook_executions` 均不回显 token 明文、Authorization Header、Webhook Secret 或 Callback Token。
- health check 执行受控 `GET {endpoint_url}{health_check_path}`，2xx 为 healthy，3xx 记 warning，4xx/5xx/timeout/DNS/TLS/连接错误按失败策略累计；达到阈值后进入 warning / error，成功后恢复 healthy 并清零 failure_count。
- health check 结果统一写入 `hook_executions(service_type=external_service, hook_name=external_service.health_check)`，便于运行记录 / 审计和插件详情排障。
- 插件 disabled / archived / soft_uninstalled 时 external_service 不调用 endpoint，只记录 skipped；external_service 状态进入插件健康摘要，后台详情抽屉展示外部服务地址、健康状态、超时、失败策略、认证方式、失败次数、最近检查和最近失败原因。
- 本轮不执行第三方插件代码，不开放动态加载，不开放远程 iframe URL，不做 JS 注入，不做 blocking Hook，不改变 Webhook Secret / Callback Token 安全模型。
