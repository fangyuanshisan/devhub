# DevHub v1.8.3：后台插件治理页面稳定性与中文体验优化版

[返回文档入口](../README.md)

日期：2026-05-18

## 版本定位

v1.8.3 定义为“后台插件治理页面稳定性与中文体验优化版”。

本轮只优化后台插件治理页面稳定性、页面结构、页内 Tab、详情抽屉分组、中文文案、空状态、危险操作提示和安全边界说明；不修改插件底层生命周期逻辑，不修改 Webhook 协议，不修改 Secret / Callback Token 安全模型。

## 已完成

### v1.8.3-S1：后台插件治理页面稳定性修复与 IA 第一批收敛

- Webhook 治理页继续使用安全列表响应归一化，接口返回 `null` / 缺少 `items` 时仍显示中文空状态，不再因为 `.length` 读取导致白屏。
- 插件详情抽屉补齐 `maturityLabel` 导入，并增加有效插件兜底；无效插件对象不会继续渲染详情主体，依赖列表也过滤空依赖和空插件项。
- 插件列表数据源在 `usePluginData` 中过滤 `null` / 缺少 `code` 的插件项，避免概览、列表和详情入口读取 `plugin.code` 报错。
- 左侧插件导航维持 5 个治理域：插件总览、插件包治理、Webhook 治理、可信发布者、运行记录 / 审计；低频入口继续归入对应治理域。
- 插件列表做第一批减负：健康摘要默认折叠，首屏表格保留插件、版本、能力摘要、最近操作、操作等关键列；插件类型、状态、健康和官方内置标识合并到插件主列展示。
- `official_announcement` 在插件列表中显示“官方公告插件”和“官方内置”标识，能力摘要突出前端挂载、配置和 iframe 预览。
- 上传包详情默认先显示状态摘要、建议动作和可用操作，原始 zip 扫描、清单文件校验、风险报告、错误详情、安装预检 JSON 折叠到“技术详情”。
- 可信发布者页面做信息密度优化：主列表突出发布者、可信级别、状态、影响范围和操作，`publisher_id` / `key_id` 弱化到发布者主列，指纹和公钥保留在详情中。
- 插件包治理和上传包相关文案继续统一为“预检 / 清单文件 / 校验和 / 暂存区 / 本地仓库”等中文后台语义。
- 修复 `/admin-next/plugins/operations` 操作历史页响应解包错误：兼容已由 `http` 拦截器解包的业务响应与 axios `{ data }` 响应，列表返回空对象 / 空响应时显示“暂无操作记录”，不再读取 `undefined.items`。

### v1.8.3 主体收敛

- 修复 Webhook 治理页空数据 / 缺字段时的白屏风险：Events、Deliveries、Retry、Circuit Breakers、Secrets、Callback Tokens、Callback Requests 均通过安全默认值和中文空状态渲染。
- 修复插件详情抽屉运行时异常：补齐 `maturityLabel` 导入，并避免配置版本弹窗在插件对象为空时读取 `plugin.code`。
- 左侧插件导航收敛为 5 个治理域：插件总览、插件包治理、Webhook 治理、可信发布者、运行记录 / 审计；旧路由仍保留并归入对应治理域。
- 插件详情抽屉新增更清晰的三级 Tab 分组：概览、配置、前端挂载、Webhook、Webhook 密钥、回调 Token、运行记录、审计日志等能力不再全部平铺在首页。
- 插件列表页补齐插件类型、能力摘要、子站启用情况、最近操作、查看详情/配置/启用/停用/软卸载/升级/查看审计等中文操作入口。
- Webhook 治理页按场景拆分为：事件、投递记录、重试队列、熔断状态、Webhook 密钥、回调 Token、回调请求。
- 插件包治理页保留“本地仓库 / 初始化插件包 / 上传 zip”页内 Tab，并补充远程索引、暂存区、预检、兼容性检查、启用前检查、升级不会执行第三方代码等边界说明。
- 上传记录、远程插件包、审批中心、操作历史、配置版本历史/回滚预览等治理页面补齐中文字段、中文状态、中文按钮、空状态和高风险动作确认。
- 可信发布者页将状态、可信级别、允许/阻断插件、过期时间、最近使用、按钮、确认弹窗和详情字段中文化，明确发布者变更会影响包验签与安装准入。
- `official_announcement` 在插件详情中补充官方内置、前端挂载模型验证、不执行第三方代码、仅允许内置 iframe 页面、不暴露 callback token / webhook secret 等说明。
- 补齐统一状态展示：enabled / disabled / retry_scheduled / retry_exhausted / circuit_open / half_open / revoked / expired 等后台状态以中文 badge 展示。
- `dry-run` 在用户可见操作中统一表述为“预检”，技术字段和 JSON key 仍保留原值以便排障。
- 修复 `scripts/check-frontend.sh` 在 Docker named volume 已被 root 创建时无法写入 `node_modules/.vite-temp`、`test-results`、`playwright-report` 的问题：检查脚本会在运行前用 root 容器修正对应 workspace 目录属主，再按当前 UID/GID 执行实际构建与 E2E。

## 安全边界

- 仍不开放远程 iframe URL。
- 仍不执行第三方插件代码。
- 仍不做 JS 注入。
- 仍不开放插件市场。
- 仍不做 blocking Hook。
- Webhook Secret 和 Callback Token 明文仍只展示一次，列表和详情不展示明文。
- Callback Token 仍不是管理员权限，只能访问授权 Scope。
- 停用插件会停止前端挂载和 Webhook 投递；软卸载保留历史数据但停止新能力。

## 未改变

- 插件生命周期底层逻辑未改变。
- Webhook delivery / retry / circuit breaker 核心逻辑未改变。
- Secret / Callback Token 安全模型未改变。
- Host + iframe + postMessage 协议未改变。
- `/topics/:id` SEO、`/c/:slug` SEO、`sites/posts` 兼容 API 未改变。
