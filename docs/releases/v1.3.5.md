# DevHub v1.3.5 Draft

定位：插件治理体验与安装升级向导收口版。

本文是 `v1.3.5` 迭代集合（历史草案/追溯用）。本文撰写时仓库 `VERSION` 仍为 `v1.3.4`；当前仓库已切到 `v1.4.0`，以 `docs/PROJECT_PROGRESS.md` 与 `docs/releases/v1.4.0.md` 的验收记录为准。

## 目标

`v1.3.5` 聚焦把 `v1.3.4` 已落地的插件平台基础能力做成更清晰、更安全、更容易验收的后台治理体验。它不新增插件市场、不执行第三方代码、不做动态加载，也不做具体业务插件字段。

## P0 必做

1. 后台插件治理中心信息架构重排。
   - 优化 `/admin-next/plugins` 的总览、筛选、批量操作、插件列表和详情治理层级。
   - 表格减少横向拥挤，操作列改为“详情 / 配置 / 更多”分组。
   - 危险操作继续二次确认，不能因为 UI 优化降低安全性。

2. 完整安装向导。
   - 将 Manifest 校验、dry-run 预览、安装确认拆成真正分步式向导。
   - 结构化展示 `errors`、`warnings`、`dependencies`、冲突、迁移计划和安装影响。
   - 安装前必须确认，Manifest 校验和 dry-run 不写入状态。

3. 完整升级向导。
   - 将升级拆成“粘贴 / 上传 manifest -> 兼容性与影响预览 -> 确认执行”三步。
   - 复用现有 `upgrade dry-run` 和 `upgrade` 接口。
   - 明确展示版本兼容矩阵、配置兼容、迁移计划、权限 / 菜单 / 路由 / Hook diff。
   - 当前不做回滚、migration down 或危险删除。

4. 批量归档 / 恢复体验补强。
   - 增加批量操作前影响预览。
   - 结果面板展示 `succeeded` / `failed` 表格和失败原因。
   - 操作后提供审计跳转入口。

5. 状态治理页收口。
   - 将“状态治理”定位为异常处理入口，而不是第二个插件列表。
   - 展示异常插件、迁移待处理、Hook 异常、配置无效、依赖缺失和归档插件。
   - 点击异常项进入插件详情对应 Tab。

6. PluginContent 体验对齐。
   - 页面头部展示插件名称、插件编码、内容类型、插件状态和健康状态。
   - 已归档 / 已禁用插件提示“不能新建，但历史内容仍可治理”。
   - 保持筛选、详情、多选、批量隐藏 / 恢复和审计跳转不退化。

## 当前实现进展

- `/admin-next/plugins` 已完成第一轮信息架构重排：页面头部主操作、列表 / 状态治理双视图、核心统计卡、健康摘要、筛选面板、批量操作面板、精简插件表格和“详情 / 配置 / 更多”操作分组。
- 安装向导已从结构化工作面板升级为抽屉分步流程：输入 Manifest、校验结果、dry-run 影响预览、确认安装、安装结果。
- 升级向导已从单次操作升级为抽屉分步流程：输入 Manifest、版本兼容和变更预览、确认升级、升级结果。
- 批量归档 / 恢复已支持影响预览、二次确认、succeeded / failed 明细和审计跳转。
- 状态治理已在插件中心内形成异常处理视图，聚合迁移待处理、迁移失败、Hook 异常、配置无效、依赖缺失和归档插件。
- 本阶段最小后台 E2E 已覆盖安装向导、升级向导、批量归档 / 恢复和状态治理入口；最新结果为 `21 passed / 2 skipped`。

## 剩余收尾

- 跑一次发版前最小验收并记录结果：`go test ./...`、`go build`、后台 build、后台插件治理 E2E。
- 决定是否正式切版到 `v1.3.5`。如果切版，需要同步 `VERSION`、README 当前版本、CHANGELOG 和本文档状态；如果不切版，所有文档继续明确“v1.3.5 已在工作区实现但未发布”。
- 处理后台 E2E 中 2 条 skipped 旧链路：删除、恢复启用，或在测试文档保留替代覆盖说明。
- 对 PluginContent 做小范围体验对齐：头部状态、禁用 / 归档提示、筛选和审计入口；不扩大到专属插件业务页面。

## P1 视情况推进

- 插件内容治理操作权限矩阵继续细化。
- RBAC 权限分配 UI 草案。
- Docs / Wiki 专用体验的最小信息架构，不做复杂编辑器。
- `config_schema` 深层对象、数组和字段分组的表单体验增强。
- Hook 排障页：执行记录、失败详情、blocking / non-blocking、最近错误和手动重试入口。
- 前台和非插件后台页面 i18n 清理。

## 不做内容

- 不做插件市场。
- 不做插件包 zip 上传和远程安装。
- 不做在线更新。
- 不做 Go 动态插件加载。
- 不做 JS / WASM / Lua 脚本沙箱。
- 不执行第三方本地代码。
- 不做硬卸载。
- 不删除插件历史内容、配置、迁移记录或审计记录。
- 不重命名 `topics` / `categories`。

## 验收重点

- `/admin-next/plugins` 页面可打开，信息层级清晰。
- 安装向导、升级向导、批量归档 / 恢复都能完成最小闭环。
- 危险操作仍有确认。
- Manifest 校验、dry-run、install、upgrade dry-run、upgrade、archive、restore、bulk archive、bulk restore 入口不退化。
- PluginContent 历史治理不退化。
- 已有后台 E2E 不退化；新增最小 E2E 只覆盖新向导入口和关键状态，不扩成大矩阵。

`v1.3.5` 完成后，再进入外部服务型 Webhook、插件包签名、插件包 dry-run、生产 MySQL 大库升级演练和插件市场雏形等后续阶段。
