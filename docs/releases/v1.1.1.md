# DevHub v1.1.1 - 前后台身份边界整理版

[返回文档大纲](../README.md)

发布日期：2026-05-09

## 版本定位

DevHub v1.1.1 是“前后台身份边界整理版”。本版本不扩展大型业务功能，重点把前台用户、后台人员和子站版主三类身份的职责、登录态、API 鉴权和审计记录边界整理清楚。

## 背景

v1.1.0 已完成子站模块增强，子站具备独立首页、SEO、配置、板块、版主、统计、关注和公告能力。随着后台治理和子站版主能力增长，必须避免 `users`、`admin_users` 和 `community_moderators` 在权限、审计、通知、动态中继续混用。

## 身份模型

- `users`：前台用户，用于注册、登录、发帖、评论、点赞、收藏、关注、举报、我的动态和我的通知。
- `admin_users`：后台人员，用于登录 `/admin-next`、后台管理、内容治理、子站管理、系统配置、用户管理和审计日志。
- `community_moderators`：子站版主授权表。版主本质仍是 `users`，通过 `community_id + user_id + status=1` 获得指定子站治理权限。

## 本次完成内容

- 前台登录 `POST /api/v1/auth/login` 返回 `token_type=user`、`aud=devhub_frontend`。
- 后台登录 `POST /api/v1/admin/login` 返回 `token_type=admin`、`aud=devhub_admin`。
- 前台 user token 不能被后台特权接口当作后台人员。
- 后台 admin token 不能被前台用户接口当作 `users` 身份。
- `/api/v1/admin/*` 默认使用后台身份；已启用子站版主可用 user token 进入允许的治理接口，并被限制在自己负责的子站。
- 前台推荐 token key 为 `devhub_user_token`、`devhub_user_refresh_token`，兼容读取旧 `devhub_access_token`、`devhub_refresh_token`。
- 后台继续使用独立 `devhub_admin_token`、`devhub_admin_refresh_token`。
- `admin_logs` 补充并读写 `actor_type`、`actor_id`，区分 `admin_user`、`moderator` 和 `system`。
- 后台审计页面展示操作者身份类型，并支持 `actor_type` 筛选。

## 不做内容

- 不重构整个认证系统。
- 不引入 OAuth、SSO 或第三方登录。
- 不做复杂后台 RBAC 大重构。
- 不做声望体系、用户主页、推荐算法或标签专项能力。
- 不破坏 `/topics/:id` 和 `/c/:slug` 的 Go 动态 SEO HTML。

## 数据结构变化

- `refresh_tokens.token_type`：区分 `user` / `admin` refresh token。
- `admin_logs.actor_type`：记录 `admin_user`、`moderator` 或 `system`。
- `admin_logs.actor_id`：记录操作者 ID；`admin_user` 对应 `admin_users.id`，`moderator` 对应 `users.id`。

旧库由启动迁移辅助尽量补齐字段。生产升级仍建议先在预发库执行并验证。

## 已知限制

- MemoryStore 仍使用轻量 demo seed 用户，属于开发兜底，不是生产身份规则。
- MySQL `refresh_tokens.user_id` 当前按 `token_type` 分别指向 `users.id` 或 `admin_users.id`，因此不再保留单一 `users` 外键；后续生产化 migration 可进一步拆分命名。
- 后台人员参与前台互动时应同时拥有一个 `users` 身份；本版本未做 admin-user 绑定关系。
- 子站版主仍复用后台治理类接口，完整独立 moderator 控制台留到后续版本。

## 最低检查

本版本最低检查：

```bash
gofmt
go test ./...
go build -o .devhub/devhub .
```

Go / Node / MySQL 检查应优先通过 Docker / docker compose / `dev.sh` 执行；Docker 镜像、权限或网络不可用时，需要明确提示用户处理。
