# v1.7.6-S1：Webhook 签名鉴权与 Secret 轮换专项验收 / 补测 / 修缺口

本轮任务：对已落地的 `v1.7.6` 做专项验收与补测，不重新实现功能；发现缺口则在 **不改变后端语义边界** 的前提下修复。

> 说明：本轮为验收/补测轮，允许修 P0/P1。  
> 仍然只处理 non_blocking Webhook；不实现 blocking Hook；不执行第三方插件代码；不实现插件回调 Core API token/scopes。

## 本轮重点验收项

1. HMAC-SHA256 发送端签名真实生效（签名 Header 完整、signing string 规则一致）。
2. `body_sha256` 与 `timestamp` 确实参与签名。
3. `secret_ref` 管理与 Secret 生命周期（create/disable/revoke/rotate，active/previous/grace period）。
4. Secret 明文不落库、不进日志/审计/delivery；创建/轮换明文只返回一次。
5. 远端 401/403 与重试/熔断联动（默认不重试）。
6. MemoryStore / MySQLStore 行为一致。
7. 后台最小 UI 可用（Secrets Tab + 关键操作）。

## 本轮修复（如有）

- 修复：当同一 `(plugin_code, target_url)` 存在 Secret 但非 active（例如被禁用）时，签名失败的 `signature_status` 更准确（返回 `secret_disabled/secret_revoked/secret_expired` 而非笼统 `secret_missing`），用于治理排障与审计追踪。
- 补测：新增 Go 单测覆盖签名 Header、signing string、签名 redaction、disabled Secret 不发送请求、远端 401 不进入重试调度等关键规则。
