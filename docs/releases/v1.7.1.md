# DevHub v1.7.1

v1.7.1 定义为“插件包签名验签与可信发布者增强版”。

本版本在 v1.7.0 远程插件包治理 P0 链路（下载到 staging → 解压安全检查/manifest 预校验 → compat-check → 安装事务 → enable-precheck → enable → 软卸载 → 升级）基础上，补齐“来源可信/未被篡改”的最小闭环：对远程包引入 detached signature（`devhub-signature.json`）并执行 **Ed25519 真实验签**，并将验签结果强联动到 compat-check / install / upgrade。

## 范围与边界

已实现：

- detached signature 元数据文件：`devhub-signature.json`。
- Ed25519 真实验签（base64 公钥 + base64 signature）。
- canonical JSON payload：对稳定结构体 `signature_payload` 进行 `json.Marshal` 得到 canonical bytes 并验签（禁止 map payload）。
- 可信发布者（公钥）治理：复用 `plugin_trusted_publishers`，并新增 `expires_at` 支持。
- 验签记录持久化：`plugin_package_signatures`。
- 联动策略：
  - 默认要求 `signature=verified` 才允许进入 staging/precheck 驱动的安装/升级链路（可通过环境变量仅在 dev 场景放开）。
  - `untrusted_publisher / key_revoked / key_expired / hash_mismatch / payload_mismatch / failed / algorithm_unsupported` 一律阻断安装/升级。
- 管理接口：
  - 预检记录验签：`POST /api/v1/admin/plugins/packages/prechecks/:id/verify-signature`
  - 验签记录列表/详情/删除：`/api/v1/admin/plugins/packages/signatures`
- 后台最小入口：在“上传包管理”页面新增 detached signature 验签区块（验签 + 列表）。
- 后台插件治理导航按“功能域分层”：一级模块（插件）→ 二级功能域分组 → 三级具体页面；状态筛选（例如插件列表已启用/已禁用/异常）改为页内 Tab，并同步 URL query。

未实现/仍不支持：

- 插件市场、远程自动更新、动态加载、第三方代码执行、sandbox。
- 完整 PKI/证书链、时间戳服务、透明日志、远程 OCSP/CRL。
- 远程索引文件自身的签名验签（仅校验 package 的 detached signature）。

## detached signature：devhub-signature.json

文件名：`devhub-signature.json`（可来自 `signature_url` 下载或包内同名文件）。

最小结构（schema_version=1）：

```json
{
  "schema_version": "1",
  "algorithm": "Ed25519",
  "publisher_id": "devhub-official",
  "key_id": "devhub-official-2026-01",
  "plugin_code": "demo",
  "version": "1.0.0",
  "package_sha256": "…",
  "manifest_sha256": "…",
  "signature": "base64…",
  "signed_at": "2026-05-16T00:00:00Z",
  "signature_payload": {
    "plugin_code": "demo",
    "version": "1.0.0",
    "package_sha256": "…",
    "manifest_sha256": "…",
    "publisher_id": "devhub-official",
    "key_id": "devhub-official-2026-01",
    "compatible_core_version": ">=1.7.0 <2.0.0"
  }
}
```

验签绑定规则（阻断项）：

- `signature_payload.package_sha256` 必须等于 staging download 的实际 `sha256_actual`。
- `signature_payload.manifest_sha256` 必须等于预检目录中 `manifest.json` 实际 sha256。
- `signature_payload.plugin_code/version/compatible_core_version` 必须与 `manifest.json` 一致。
- `publisher_id + key_id` 必须能匹配本地可信发布者记录，且状态为 `trusted`，且未过期（`expires_at`）。
- `algorithm` 仅支持 Ed25519（大小写不敏感）。

## 可信发布者（trusted publishers）

复用 `plugin_trusted_publishers`：

- `publisher_id + public_key_id` 唯一。
- `status`：`trusted / blocked / revoked`（`blocked/revoked` 阻断验签信任）。
- 新增：`expires_at`（过期后阻断验签信任）。
- 仅保存公钥，不保存私钥；后台不会展示/导入私钥。

## 签名文件来源与限制

- `signature_url`：在下载阶段记录（仅记录，不在下载阶段强制阻断），验签时按同一套 URL/SSRF 规则下载签名文件。
- 包内 `devhub-signature.json`：验签时读取。
- 若同时存在 `signature_url` 与包内签名，且 JSON 内容不一致：验签失败（阻断）。

限制：

- `signature_url` 仅允许 HTTPS + `.json`，最大 64KB，最多 3 次重定向（每次重定向重新校验）。

## 安装/升级联动策略

- 默认策略：`DEVHUB_PLUGIN_REQUIRE_SIGNED_PACKAGES` 未设置时视为开启（要求 verified）。
- compat-check：缺少验签记录或非 `verified` 会使 `can_install=false`。
- install/upgrade：在执行前会再次要求验签记录为 `verified`（避免仅靠前端状态绕过）。
- 生产环境不建议允许 unsigned；如需 dev 环境放开请显式设置 `DEVHUB_PLUGIN_REQUIRE_SIGNED_PACKAGES=0` 并接受审计风险。

## 数据库变更

- `plugin_package_downloads`：新增 `signature_url`。
- `plugin_package_signatures`：新增 detached signature 验签记录表。
- `plugin_trusted_publishers`：新增 `expires_at`。

## 配置项 / 环境变量

- `DEVHUB_PLUGIN_REQUIRE_SIGNED_PACKAGES`：默认启用；设置为 `0/false` 可在 dev 场景放开 unsigned（仍会产生审计与风险提示）。
- `DEVHUB_PLUGIN_PACKAGE_SIGNATURE_MAX_BYTES`：签名文件最大下载大小，默认 64KB。
- `DEVHUB_PLUGIN_PACKAGE_SIGNATURE_STAGING_ROOT`：签名文件 staging 目录，默认 `storage/plugins/staging/signatures`。
