# DevHub v1.6.0 Release Notes

定位：插件包导入体验与安全沙箱增强阶段。

当前 v1.6.0 仍处于开发阶段；本页只记录已真实落地能力，不把后续规划写成已完成。

## v1.6.0-P0-01：后台初始化插件包（已落地）

目标：把 CLI `plugin:new` 的声明型插件模板生成能力优化为后台“初始化插件包”入口，让管理员可在后台填写插件基础字段并生成本地插件仓库包。

已完成：

- 后端抽取模板生成服务，CLI 与 HTTP handler 复用同一套生成逻辑。
- 新增 API：
  - `POST /api/v1/admin/plugins/packages/templates/preview`
  - `POST /api/v1/admin/plugins/packages/templates`
- 后台入口：`系统插件 -> 安装升级 -> 初始化插件包`。
- 后台表单字段：`code`、`name`、`content_type`、`content_name`、`description`、`author`、`with_config`、`with_hooks`、`with_migration`。
- 输出目录固定为 `storage/plugins/packages/{code}`，不接受任意 path，不暴露 `force`，目录已存在时拒绝覆盖。
- 后台初始化版默认不生成 `registry.example.go`，改生成 `docs/registry-example.md`，避免 `.go` 文件触发插件包 dangerous file blocked。
- 初始化成功后写入审计日志，并自动执行 package dry-run，返回插件包路径、dry-run 状态、风险等级、manifest 校验结果、warnings/errors。
- dry-run 未 blocked 时，后台允许继续提交安装审批；直接安装仍按现有 `plugin.approve` 权限执行。

边界：

- 不做 zip 上传。
- 不做远程市场 / 远程下载。
- 不做动态加载代码。
- 不执行插件代码。
- 不执行 SQL。
- 不生成前端动态页面。
- 不改变插件运行时边界。

验证记录：

- `gofmt`：通过。
- `go test ./...`：通过。
- `go build -o .devhub/devhub .`：通过。
- `bash -n dev.sh`：通过。
- `bash -n scripts/check-frontend.sh`：通过。
- `git diff --check`：通过。
- `./scripts/check-frontend.sh --admin-only`：通过，后台 build 通过，后台 Playwright `49 passed`。

说明：本轮只改后台插件安装升级页和后端插件包模板 API，不涉及前台页面、前台导航或 SEO 共享逻辑，因此未执行 `--frontend-only` 与 SEO curl。
