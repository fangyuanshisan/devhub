## 阶段定位

v1.6.0 进入“插件包上传与分发前置能力”阶段。P0-01 的目标是允许管理员上传 zip 插件包，并在受控目录内进行安全解压、扫描、checksum 校验、签名草案检查、风险报告和 dry-run 预览。

本轮仍不支持远程插件市场、远程下载、在线更新、上传后自动安装、动态加载 Go 代码、JS/WASM/Lua 脚本沙箱、第三方代码执行、外部 SQL 执行、动态加载前端资产、完整市场发布审核、评分评论、插件运行时、hard uninstall、migration down 或复杂异步任务队列。

## 安全边界

上传限制：

- 只允许 `.zip`。
- 上传 zip 最大 20MB。
- 解压后总大小最大 50MB。
- 单文件最大 5MB。
- 文件数最大 300。
- 目录深度最大 8。
- zip 内嵌压缩包默认 blocked。

zip slip 防御：

- 禁止 `../`、`dir/../../evil`。
- 禁止 `/etc/passwd` 等绝对路径。
- 禁止 Windows 盘符路径。
- 禁止空文件名、过长文件名、`\0`。
- 禁止 `%2e`、`%2f`、`%5c` 等可疑编码绕过。
- 解压前后均确认输出路径位于当前 upload 的 staging 目录内。

zip bomb 防御：

- 限制上传大小、解压总大小、单文件大小、文件数量、目录深度。
- 阻断重复 entry / 重复输出路径。
- 阻断嵌套压缩包。
- 阻断 symlink、非常规文件；解压后 scanner 继续检测 hardlink / dangerous files。
- 当前未实现压缩比阈值检查，后续可补充。

插件包根目录识别：

- 根目录直接有 `manifest.json`：使用根目录。
- 只有一个顶层目录且该目录内有 `manifest.json`：使用该顶层目录。
- 无 manifest：blocked。
- 多 manifest：blocked；本轮不支持批量插件包 zip。

promote 行为：

- 只有 staging 中 `ok|warning` 且非 blocked 的包可 promote。
- promote 前重新 dry-run，复制后再次 dry-run。
- 目标目录已存在默认拒绝。
- promote 不安装插件、不执行代码、不执行 SQL、不动态加载资产。

## v1.6.0-P0-02 插件包 zip 导入审批增强与上传包生命周期治理

已完成：

- 新增 `plugin_package_uploads` 上传包记录模型，MemoryStore / MySQLStore 均支持新增、保存、按 `upload_id` 查询和列表筛选。
- 上传 zip 后创建生命周期记录：`uploaded -> scanned -> staged/blocked`；默认 `expires_at` 为 7 天。
- 新增上传包状态：`uploaded`、`scanned`、`blocked`、`staged`、`approval_pending`、`approval_rejected`、`approved`、`promoted`、`install_approval_pending`、`installed`、`canceled`、`expired`、`deleted`、`failed`。
- 新增上传包列表 API：`GET /api/v1/admin/plugins/packages/uploads`。
- 增强上传包详情 API：`GET /api/v1/admin/plugins/packages/uploads/:upload_id` 返回 record、扫描快照、审批信息和 actions。
- 新增重新扫描 API：`POST /api/v1/admin/plugins/packages/uploads/:upload_id/rescan`。
- 新增导入审批 API：`POST /api/v1/admin/plugins/packages/uploads/:upload_id/approval`，复用 `plugin_approval_requests`，action 为 `package_promote`。
- 新增上传包导入审批通过 / 拒绝 API：`POST /approve`、`POST /reject`。
- 增强 promote：只允许 `staged/approved`，promote 前重新 dry-run，复制后复检；promote 后状态变 `promoted`，仍不安装插件。
- 新增取消、删除和手动 cleanup：`POST /cancel`、`DELETE /:upload_id`、`POST /cleanup`。
- 后台新增 `/admin-next/plugins/packages/uploads` 上传包管理页，支持上传、筛选列表、详情抽屉、rescan、审批、promote、cancel、delete、cleanup。

状态流转规则：

- `blocked/deleted/expired/canceled` 不能 promote，不能进入安装审批。
- `staged/approved` 可以 promote。
- `approval_pending` 不能 promote，必须审批通过或拒绝。
- `promoted` 删除只清理 upload / staging 文件，不删除 `storage/plugins/packages/` 本地仓库包。
- cleanup 只清理 `expired/deleted/canceled/failed` 上传包文件，不删除本地仓库或已安装插件。
- 本轮不做自动过期定时任务，只在手动 cleanup 时处理 `expires_at`。

审批增强：

- 导入审批对象是上传包 promote，不等同插件安装审批。
- 审批通过后仍需 promote 前重新扫描 / checksum / signature / risk_report / manifest validate / dry-run。
- blocked 上传包不能提交导入审批。
- `package_promote` 审批快照包含 `upload_id`、zip scan、file scan、signature、trust、risk_report 和 dry-run。

安全边界保持不变：

- 不支持远程插件市场、远程下载、在线更新、上传后自动安装、动态加载 Go 代码、JS/WASM/Lua 脚本沙箱、第三方代码执行、外部 SQL 执行、动态加载前端资产、完整市场发布审核、多级审批、通知推送、复杂异步队列、hard uninstall 或 migration down。

## v1.6.0-P0-03 插件包真实签名验签与可信发布者管理界面

已完成：

- `signature.json` 支持 Ed25519 真实验签，签名消息固定为 `sha256(raw bytes of checksums.json)`；`algorithm` 仅支持 `ed25519`，`payload` 仅支持 `checksums.json`，`payload_algorithm` 仅支持 `sha256`。
- `publisher.json` 仍只是包内发布者声明，不会自动建立信任。
- 新增 `plugin_trusted_publishers` 可信发布者存储，字段包括 `publisher_id`、`public_key_id`、`public_key_algorithm`、`public_key`、`fingerprint`、`status`、`notes`、创建 / 更新时间和 metadata。
- 新增可信发布者 API 与后台 `/admin-next/plugins/trusted-publishers` 页面；查看需 `plugin.read`，新增 / 修改 / block / revoke / restore / 删除需 `plugin.manage`。
- `trusted` / `unknown` / `blocked` / `revoked` 规则已接入 package dry-run、仓库扫描、zip 上传详情、promote、install 与 approval 执行前重新校验。
- `verification_status` 使用 `verified|failed|missing|unsupported|publisher_unknown`；真实验签通过时不再显示 `structural_only`。
- `risk_report` 接入签名结果：`trusted+verified` 不新增风险，`unsigned` 为 medium warning，`unknown publisher` 为 high，`verification failed` / `unsupported` / `blocked` / `revoked` 为 blocked。

仍不支持：

- 远程可信源同步、远程插件市场、远程下载、在线更新、自动安装依赖、完整 PKI / CA 证书链、私钥管理后台、在线签名服务、动态加载、脚本沙箱、第三方代码执行、外部 SQL 和动态前端资产。

## v1.6.0-P1-07 插件配置密钥轮换策略

已完成：

- 新增插件配置加密 keyring：支持 `DEVHUB_PLUGIN_CONFIG_KEYS`（JSON，current+keys）与 split 形式 `DEVHUB_PLUGIN_CONFIG_KEY_ID/DEVHUB_PLUGIN_CONFIG_KEY/DEVHUB_PLUGIN_CONFIG_OLD_KEYS`；保留 `DEVHUB_PLUGIN_CONFIG_KEY` legacy 兼容。
- 敏感字段密文升级：新写入使用 `enc:v2:<key_id>:<nonce>:<ciphertext>`；兼容读取 `enc:v1:<nonce>:<ciphertext>`，并可通过 re-encrypt 转换为 v2。
- 新增密钥状态与轮换 API：
  - `GET /api/v1/admin/plugins/config-keys/status`
  - `POST /api/v1/admin/plugins/config-keys/rotation/dry-run`
  - `POST /api/v1/admin/plugins/config-keys/rotation/re-encrypt`
- 新增后台页面：`/admin-next/plugins/config-keys`（不展示 key material / 不展示密文，提供预检与受控 re-encrypt）。

限制 / 边界：

- 不支持 KMS/Vault、自动定时轮换、多租户独立密钥、后台读取或展示密钥明文。
- 默认不处理配置历史版本（`include_config_versions=false`）；配置历史轮换留到后续版本。
