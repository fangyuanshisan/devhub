# v1.7.7：Webhook 受控 Core API 回调 Token 与权限 Scope 增强版

更新时间：2026-05-17

本轮定位：在 v1.7.6 Webhook 签名鉴权与 Secret 轮换基础上，为外部 HTTP 插件服务提供“受控回调 DevHub Core API”的最小通道。

> 重要边界：本轮不实现 blocking Hook、不执行第三方插件代码、不做动态加载、不做插件市场、不做 OAuth/SSO、不提供通用插件 SDK。

## 本轮完成

### 1) Callback Token（插件服务 → Core）能力

- 新增 `plugin_callback_tokens`：用于外部插件服务回调 Core API 的 Bearer Token（仅保存 `token_hash`，不落库明文）。
- Token 支持：创建 / 禁用 / 恢复 / 吊销 / 轮换（轮换默认吊销旧 Token）。
- Token 明文仅在创建 / 轮换响应中展示一次；列表/详情均不返回明文。
- Scope 白名单最小落地：`config.read`、`audit.write`（未知 scope 直接拒绝）。
- Community scope：创建 token 时必须显式提供 `community_scope`，避免默认全社区可用；回调请求会校验 `community_id` 是否在 scope 内。

### 2) 最小插件回调 API

命名空间：`/api/v1/plugin-callback/*`（注意：不是 admin API，不使用 admin token）。

- `GET /api/v1/plugin-callback/config`（需要 `config.read`）
  - 只能读取 token 所属 `plugin_code` 的配置（按 `community_id` 获取 effective config）。
  - 返回已脱敏配置（基于 `config_schema`）。
- `POST /api/v1/plugin-callback/audit-events`（需要 `audit.write`）
  - 仅允许写入以 `plugin_code.` 前缀开头的审计 action，防止伪造 Core/admin 审计。

### 3) Callback Request 记录与审计

- 新增 `plugin_callback_requests`：记录每次 callback API 调用（包含 rejected 场景；不保存 token 明文）。
- 审计动作补齐（示例）：
  - `plugin.callback_token.*`
  - `plugin.callback.request.accepted/rejected`
  - `plugin.callback.scope.denied`
  - `plugin.callback.community_scope.denied`
  - `plugin.callback.config.read`
  - `plugin.callback.audit.write`

### 4) 后台最小治理入口（admin-next）

在 `Webhook 治理` 页面增加页内 Tab（页内状态不进入左侧菜单）：

- Callback Tokens：列表/筛选/创建/轮换/禁用/恢复/吊销（Token 明文仅弹窗展示一次）
- Callback Requests：列表/筛选/分页

## 本轮未做 / 明确不支持

- 不支持 blocking Hook。
- 不实现插件回调 Core API 的完整 token/scopes 体系（仅最小 scope 白名单）。
- 不实现插件代表用户操作（actor 代理）能力。
- 不提供通用插件 SDK（仅后端能力与文档说明）。
- 不执行第三方插件代码，不做 Go plugin/.so 动态加载。

## 数据库与初始化影响

- 新增表：
  - `plugin_callback_tokens`
  - `plugin_callback_requests`
- 需要同步 `db/mysql/001_schema.sql`；MemoryStore/MySQLStore 行为保持一致。
