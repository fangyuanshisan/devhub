# DevHub v1.3.0 - Core + Plugins 架构拆分版

[返回文档大纲](../README.md)

发布日期：2026-05-10

## 版本定位

DevHub v1.3.0 将问答、文档、Wiki 从核心内容类型中拆分为内置系统插件。Core 只保留通用社区能力；`qa`、`docs`、`wiki` 插件分别注册自己的内容类型、菜单、权限和路由描述。

## 本版本完成内容

- 新增 `plugins` 表，支持 `installed`、`enabled`、`disabled` 状态。
- 新增 `community_plugins` 表，支持每个子站独立启用/禁用插件（插件需同时满足“全局 enabled + 子站 enabled”才可使用）。
- 新增插件注册定义：插件名称、版本、内容类型、后台菜单、权限码、路由描述。
- `topics` 增加 `plugin_code`，作为当前兼容实现中的 Core 内容表。
- `categories` 增加 `plugin_code` 和 `allowed_content_types`，作为当前兼容实现中的 Core 板块表。
- 新增 `internal/plugins/qa`、`internal/plugins/docs`、`internal/plugins/wiki`。
- 新增 QA 插件表：`qa_questions`、`qa_answers`。
- 新增 Docs 插件表：`docs_spaces`、`docs_documents`。
- 新增 Wiki 插件表：`wiki_spaces`、`wiki_pages`、`wiki_page_versions`。
- 发布内容时校验板块插件绑定、插件启用状态和允许内容类型。
- 后台新增“系统插件”管理入口，并提供 qa / docs / wiki 插件内容管理页（通过系统插件列表进入，插件业务页默认不出现在左侧导航）。
- 后台新增子站插件管理接口与入口（在子站管理页内配置某个子站启用哪些插件）。
- 前台兼容旧 `doc` / `wiki` 参数，并归一到 `document` / `wiki_page`。
- 前台发布页按“启用插件 + 板块 `allowed_content_types`”收口内容类型选择；禁用插件的内容类型不可选择/不可发布。

## Core 与 Plugins 边界

Core 负责用户、子站、板块、通用内容、评论、标签、搜索、通知、权限、审计、SEO 和插件注册。

Plugins 负责插件自己的内容类型和扩展能力：

- `qa`：`question`、问题、回答、采纳、已解决状态。
- `docs`：`document`、文档空间、文档树、文档详情。
- `wiki`：`wiki_page`、Wiki 页面、版本历史、回滚结构。

## API 范围

```http
GET /api/v1/plugins
GET /api/v1/communities/:slug/plugins
GET /api/v1/admin/plugins
GET /api/v1/admin/plugin-menus
POST /api/v1/admin/plugins/:code/enable
POST /api/v1/admin/plugins/:code/disable
GET /api/v1/moderator/plugin-menus
GET /api/v1/admin/communities/:id/plugins
POST /api/v1/admin/communities/:id/plugins/:code/enable
POST /api/v1/admin/communities/:id/plugins/:code/disable
PUT /api/v1/admin/communities/:id/plugins/:code/config
PUT /api/v1/admin/communities/:id/plugins/sort
```

权限码按 `plugin.action` 命名，例如：

- `qa.question.create`
- `qa.answer.accept`
- `docs.document.create`
- `docs.space.manage`
- `wiki.page.edit`
- `wiki.page.version.rollback`

## 兼容说明

- 未重命名 `topics` / `categories`，避免破坏现有 API、SEO 和历史数据。
- `topics` 对应需求中的 `contents`。
- `categories` 对应需求中的 `channels`。
- `doc` / `wiki` 历史内容类型会兼容归一为 `document` / `wiki_page`。
- `/topics/:id` SEO 仍由 Go 动态输出，不退化为 CSR。

## 当前限制

- 未做插件市场、插件压缩包上传安装或远程更新。
- 插件路由加载当前是注册描述 + Core 分发，尚未做独立动态模块加载。
- Docs 文档树专用编辑 UI、Wiki 协作编辑 UI 和版本回滚交互仍需后续增强。

## 验收清单（最小）

- `GET /api/v1/plugins` 仅返回 `enabled` 插件。
- `GET /api/v1/admin/plugins` 可查看并启用/禁用插件；操作会写入 audit logs。
- `GET /api/v1/admin/communities/:id/plugins` 可查看并启用/禁用某个子站的插件；全局 disabled 插件不能被子站启用。
- 禁用 `qa/docs/wiki` 后：不能发布对应内容类型，但已有内容列表与 `/topics/:id` SEO 访问不受影响。
- `POST /api/v1/topics` 发布时校验 `category.plugin_code`、插件状态和 `category.allowed_content_types`。
- `GET /api/v1/moderator/plugin-menus` 不返回 disabled 插件菜单，并按当前用户权限过滤。
- `GET /api/v1/communities/:slug/plugins` 只返回该子站可用插件（全局 enabled + 子站 enabled），供前台导航与发布页收口。
