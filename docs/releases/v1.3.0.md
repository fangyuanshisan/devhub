# DevHub v1.3.0 - Core + Plugins 架构拆分版

[返回文档入口](../README.md)

发布日期：2026-05-10

## 版本定位

DevHub v1.3.0 将问答、文档、Wiki 从 Core 硬编码内容类型拆分为内置系统插件。Core 负责通用社区能力；`qa`、`docs`、`wiki` 插件分别注册自己的内容类型、菜单、权限和路由描述。`project`、`job`、`ai_work` 也已完成插件归属迁移，但专属扩展表和完整业务闭环仍属后续任务。

完整插件系统是 v1.3.x 之后的最高优先级长期主线。v1.3.0 是 P0 插件平台收口的起点，不代表插件平台止步于内置插件；插件包、插件市场、远程安装、在线更新和动态加载能力进入后续 P2 / P3 路线。

## 本版本已完成

- 新增 `plugins` 表，支持全局插件状态 `installed`、`enabled`、`disabled`。
- 新增 `community_plugins` 表，支持每个子站独立启用 / 禁用插件。
- 新增插件注册定义：插件名称、版本、内容类型、菜单、权限码、路由描述。
- 内置系统插件声明已统一到 manifest 风格结构，补齐 `is_system`、内容类型定义、权限定义、菜单定义、路由定义、`config_schema`、依赖、最小 Core 版本与 Hook 预留字段。
- `topics` 增加 `plugin_code`，作为当前兼容实现中的通用内容表。
- `categories` 增加 `plugin_code` 和 `allowed_content_types`，作为当前兼容实现中的通用板块表。
- 新增 `internal/plugins/qa`、`internal/plugins/docs`、`internal/plugins/wiki`。
- 新增 `internal/plugins/projects`、`internal/plugins/jobs`、`internal/plugins/aiworks`。
- 新增插件表：`qa_questions`、`qa_answers`、`docs_spaces`、`docs_documents`、`wiki_spaces`、`wiki_pages`、`wiki_page_versions`。
- 发布 Topic 时校验全局插件状态、子站插件状态、板块插件绑定和允许内容类型。
- `qa` 已具备最小问答闭环：发布 `question` 时写 `qa_questions`，回答写 `qa_answers`，采纳后回写已解决状态与最佳答案。
- `docs` 已具备最小文档闭环：发布 `document` 时写 `docs_documents`，并支持基础文档树读取。
- `wiki` 已具备最小 Wiki 闭环：发布 `wiki_page` 时写 `wiki_pages` 和初始版本，编辑时追加 `wiki_page_versions`，支持版本列表读取。
- 后台提供“系统插件”入口；插件业务页通过系统插件列表进入，不默认散落在左侧导航。
- 前台兼容旧 `doc` / `wiki` 参数，并归一到 `document` / `wiki_page`。
- 历史 `project` / `job` / `ai_work` 内容已迁移到 `projects` / `jobs` / `ai_works` 插件归属，但历史 URL 和详情页 SEO 保持不变。
- 前台子站插件展示 API、后台子站插件管理 API、版主插件菜单 API 已在路由层注册。
- 后台最小体验已补齐：全局插件页可查看基础声明并执行启用 / 禁用；子站管理中的插件配置支持最小 `config_json` 编辑与数字排序。
- 前台和版主入口已开始按插件状态收口：子站导航、发布页和版主工作台插件入口会根据当前子站 enabled 插件过滤展示。

## 本版本部分完成

- 子站插件管理：API 与最小 UI 已可用，支持启用 / 禁用、`config_json` 编辑、JSON 校验和数字排序；完整浏览器矩阵、批量配置和更细致的状态提示仍待后续增强。
- 插件权限：菜单已按权限过滤；发布链路已按内容类型增加最小权限码校验（`question/document/wiki_page/project/job/ai_work`），Core 兼容类型 `article`、`news` 当前仍为粗粒度 `core.topic.create`（兼容旧 `post.create`）。
- Docs / Wiki：表结构、注册定义、基础扩展表写入和最小读取接口已具备；专用文档树拖拽、版本回滚 UI 和协作编辑体验仍待后续。
- Projects / Jobs / AI Works：已完成插件归属、发布校验、权限码、菜单声明和历史 `plugin_code` 迁移口径；专属扩展表、专属管理页和完整业务流程仍待后续。
- 插件路由：当前是注册描述 + Core 分发，不是真正动态运行时加载。
- Hook：当前已形成内置插件扩展点声明；后续 v1.3.1 已补最小内部 HookBus 调用点覆盖，但复杂插件处理器、错误日志和重试策略仍待后续完善。

## Core 与 Plugins 边界

Core 负责用户、认证、子站、板块、通用内容、评论、标签、搜索、通知、权限、审计、SEO、插件注册和分发。

Plugins 负责插件自己的内容类型和扩展能力：

- `qa`：`question`、问题、回答、采纳、已解决状态。
- `docs`：`document`、文档空间、文档树、文档详情。
- `wiki`：`wiki_page`、Wiki 页面、版本历史、回滚结构。

- `projects`：`project`、项目内容归属、发布校验、菜单和权限声明。
- `jobs`：`job`、招聘内容归属、发布校验、菜单和权限声明。
- `ai_works`：`ai_work`、AI 作品内容归属、发布校验、菜单和权限声明。

`projects`、`jobs`、`ai_works` 当前尚未具备专属扩展表和完整业务闭环。

## API 范围

```http
GET  /api/v1/plugins
GET  /api/v1/communities/:slug/plugins
GET  /api/v1/admin/plugins
GET  /api/v1/admin/plugin-menus
POST /api/v1/admin/plugins/:code/enable
POST /api/v1/admin/plugins/:code/disable
GET  /api/v1/moderator/plugin-menus
GET  /api/v1/admin/communities/:id/plugins
POST /api/v1/admin/communities/:id/plugins/:code/enable
POST /api/v1/admin/communities/:id/plugins/:code/disable
PUT  /api/v1/admin/communities/:id/plugins/:code/config
PUT  /api/v1/admin/communities/:id/plugins/sort
```

说明：`PUT /api/v1/admin/plugins/:code/config` 属于后续 `v1.3.1` 技术债收口补强，不计入 v1.3.0 初始范围。

## 兼容说明

- 未重命名 `topics` / `categories`，避免破坏现有 API、SEO 和历史数据。
- `topics` 对应目标架构中的 `contents`。
- `categories` 对应目标架构中的 `channels`。
- `doc` / `wiki` 历史内容类型兼容归一为 `document` / `wiki_page`。
- `/topics/:id` SEO 仍由 Go 动态输出，不退化为 CSR。

## 当前限制与阶段边界

- 插件市场、插件包上传、远程插件安装、在线更新或 Go 动态插件加载不属于 v1.3.0 已实现能力；它们进入 P2 / P3 插件平台路线，不作为永久排除项。
- 子站插件禁用不影响历史内容访问，只影响新发布、导航、菜单和管理入口。
- 发布校验已接入最小权限码校验（`question/document/wiki_page/project/job/ai_work`），Core 兼容类型 `article`、`news` 当前仍为粗粒度 `core.topic.create`（兼容旧 `post.create`，后续可细化权限码与配置能力）。
- v1.3.0 初始口径中，插件配置主要使用“默认配置 + `community_plugins.config_json`”两层；后续 `v1.3.1` 已补齐 `plugins.config_json` 全局配置层。
- Docs / Wiki 专用 UI 仍需后续增强。
- `qa` 当前未实现“取消采纳最佳答案”。
- `docs` 当前只支持基础文档树读取；拖拽、批量排序和更完整的空间管理 UI 仍未实现。
- `wiki` 当前已支持版本记录和版本列表，但未提供完整回滚接口。
- `projects`、`jobs`、`ai_works` 当前只完成插件归属、发布校验、权限码和菜单声明，尚未提供专属扩展表或完整业务流程。
- v1.3.0 初始插件治理审计以文本摘要为主；后续 v1.3.1 已为插件治理操作补充 `old_value` / `new_value` / `metadata_json` 结构化字段。
