# DevHub v1.3.4 Release Notes

定位：插件异常治理与验收闭环版（Plugin Failure Governance and Acceptance Closure）

本版本仍属于 v1.3.x 插件平台 P0 收口阶段。目标不是新增插件、插件市场或动态加载，而是验证异常状态下插件平台是否可控、可恢复、可审计、可验收。

## 本轮已完成

### 插件迁移失败注入与启用阻断

- 新增测试专用 failed migration 注入能力：`POST /api/v1/admin/plugins/:code/migrations/:name/e2e-fail`。
- 测试注入接口仅在 `DEVHUB_E2E_TESTING=1` 或 `CMS_STORE=memory` 可用，不作为生产治理入口。
- failed migration 会真实写入 `plugin_migrations.status=failed`。
- 插件全局启用会在 Service readiness 阶段检查 failed migration；存在失败迁移时返回明确错误并阻断启用。
- 子站插件启用复用同一 readiness 检查；存在失败迁移时不写入 `community_plugins.status=enabled`。
- 插件详情迁移 Tab 可展示 failed migration、错误信息、最近完成时间、状态和 retry 入口。
- retry 成功后 migration 状态变为 `success`，再次 retry 保持成功记录，不重复破坏数据。
- retry 成功后插件全局启用和子站启用可以恢复。
- 注入失败、重试和成功均写入审计：`plugin.migration.failed`、`plugin.migration.retry`、`plugin.migration.success`。

### HookBus blocking / non-blocking 失败注入与可观测

- 新增测试 / 开发环境专用 Hook 失败注入能力：`POST /api/v1/admin/plugins/:code/hooks/:name/e2e-fail`。
- 注入接口仅在 `DEVHUB_E2E_TESTING=1` 或 `CMS_STORE=memory` 可用，不作为生产治理入口。
- `BeforeCreateContent` 等 blocking Hook 注入失败后，内容创建会被后端阻断，不写入脏数据。
- `AfterCreateContent` 等 non-blocking Hook 注入失败后，内容创建仍成功，失败进入执行记录与审计。
- 两类失败都会写入 `hook_executions`；blocking 失败写入 `plugin.hook.blocked`，non-blocking 失败写入 `plugin.hook.failed`。
- 插件详情 Hooks Tab 可展示执行次数、失败次数、平均耗时、最近执行、最近失败和最近错误，E2E 已覆盖失败摘要可见。

### 插件权限矩阵收口

- 内容创建权限来源统一为 `ContentTypeDefinition.create_permission`。
- 插件内容类型使用各自插件 create 权限：`qa.question.create`、`docs.document.create`、`wiki.page.create`、`projects.project.create`、`jobs.job.create`、`ai_works.work.create`。
- Core 兼容内容类型 `article/news` 继续使用 `core.topic.create`。
- `post.create` 仅作为 `core.topic.create` 的历史兼容桥；不能替代任何插件 create 权限。
- `Service.CreateTopic` 缺权限时返回明确错误，例如“缺少权限 qa.question.create，不能创建该类型内容”。
- API 测试覆盖：仅拥有 `post.create` / `core.topic.create` 不能创建 `question`；拥有 `qa.question.create` 才能创建 `question`；`post.create` 仍可兼容 Core `article`。
- 普通前台 token 调用插件治理 API 会被后端拒绝；版主插件菜单继续按全局状态、子站状态、community scope 和插件权限过滤。

### MySQLStore 与老库升级专项

- 修复 `004_community_plugins.sql` 的老库执行顺序风险：该迁移现在会先确保 `plugins` 表存在，再创建和回填 `community_plugins`。
- 修复 `005_core_plugins.sql` 的重复执行风险：`topics.plugin_code`、`categories.plugin_code`、`categories.allowed_content_types` 改为 MySQL 8 `INFORMATION_SCHEMA + PREPARE` 幂等补列。
- 新增可选 MySQL 集成测试 `TestMySQLStorePluginPlatformConsistency`，默认跳过，仅在 `DEVHUB_MYSQL_TESTS=1` 且测试库名包含 `test` 时运行。
- MySQLStore 专项覆盖新装结构、升级字段、全局 / 子站插件启停强拦截、failed migration 阻断与 retry、Hook 记录查询、插件治理审计查询和配置 schema 校验。
- 显式 SQL 升级脚本 `004`-`010` 已在 MySQL 测试库连续执行两轮通过。

### 插件健康状态与审计定位

- `GET /api/v1/admin/plugins` 的 `health` 摘要增加 `status_reason`，用于解释插件当前主要状态原因。
- 插件健康状态补充 `hook_warning` / `hook_error`：Hook 失败存在时进入 warning，当前失败次数达到轻量阈值（`>= 3`）时进入 hook error。
- 插件详情运行状态 Tab 展示 overall、status reason、config、migration、Hook、dependency、最近错误和建议操作。
- 插件详情审计 Tab 支持按 `plugin_code`、`community_id`、`action`、`actor`、`target_type`、`target_id`、`metadata`、`request_id` 和时间范围过滤。
- Hook 失败审计会把 Hook metadata 写入 `metadata_json.hook_metadata`，便于通过 request_id / metadata 定位异常。

## 当前限制

- 当前迁移 runner 仍是内置 up/no-op 记录型 runner；真实 DDL runner、外部插件迁移包、migration down、硬回滚和迁移前备份仍未实现。
- failed migration 注入接口只服务自动化测试；生产环境真实失败仍应由 migration runner 写入。
- MySQLStore / 老库升级专项已覆盖插件平台结构和核心行为；生产大库升级仍需额外备份、预发演练、耗时评估和回滚验证。
- HookBus Search / Notification / SEO 当前仍是最小事件派发，不代表完整搜索、通知或结构化 SEO 插件业务处理器已完成。
- 插件权限矩阵仍需补更完整的 RBAC 分配 UI、category 级权限配置和插件内容治理操作矩阵；但 `post.create` 兼容桥已限定在 Core `core.topic.create`。
- 插件健康状态是轻量治理摘要，不是完整监控 / 告警系统；`hook_warning` / `hook_error` 阈值后续可随告警策略调整。
- 审计筛选仍基于 `admin_logs` 文本 / JSON 字段查询；大规模生产审计检索后续需要索引策略和归档策略。

## 验收记录

本轮新增：

- API 测试覆盖 failed migration 阻断全局启用、阻断子站启用、retry 恢复、success 不重复破坏数据和审计定位。
- 后台 E2E 覆盖迁移 Tab 可见失败原因、retry 后状态恢复、全局 / 子站启用恢复和审计可查。
- API 测试覆盖 HookBus blocking 失败阻断创建、non-blocking 失败不阻断创建、`hook_executions` 查询和 `plugin.hook.blocked` / `plugin.hook.failed` 审计。
- 后台 E2E 覆盖 Hook 失败注入、Hooks Tab 失败摘要、审计定位和注入清理。
- API 测试覆盖插件 create 权限映射、`post.create` 兼容桥边界、插件 create 权限放行和普通前台 token 禁止调用插件治理 API。
- MySQL 集成测试覆盖插件平台新装结构、升级字段和 MySQLStore 核心行为；SQL 验证覆盖 `004`-`010` 插件迁移脚本连续两轮执行。
- Go 测试覆盖 `healthy`、`config_invalid`、failed migration `error`、Hook 多次失败 `hook_error` 状态来源，并覆盖插件审计按 `plugin_code/action/community_id/metadata/request_id` 组合筛选。
- 后台 E2E 覆盖插件详情运行状态 Tab、Hook 失败摘要、迁移失败恢复和审计筛选基础路径。

本轮最低检查命令以 `docs/PROJECT_PROGRESS.md` 的最新记录为准。
