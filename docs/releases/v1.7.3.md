# DevHub v1.7.3

v1.7.3 定义为“Webhook / HTTP 插件服务协议实现拆解与官方示例插件验证准备版”。

本版本延续 DevHub “Core + 插件 的开源服务底座”方向：在 `docs/PLUGIN_WEBHOOK_PROTOCOL.md` 的协议设计基础上，把实现落地拆成可验收的阶段任务，并准备官方示例插件用于后续端到端验证。本轮只修改文档，未修改代码，未执行测试、构建或 E2E。

## 本轮新增/更新

新增：

- `docs/PLUGIN_WEBHOOK_IMPLEMENTATION_PLAN.md`：Webhook 协议实现拆解（阶段 0~6）。
- `docs/plugins/official-announcement-plugin.md`：官方公告插件端到端验证方案。

更新：

- `docs/PROJECT_PROGRESS.md`：记录 v1.7.3 拆解结论与下一阶段建议。
- `docs/PLUGIN_SYSTEM_ROADMAP.md`：补充实现阶段优先级（non_blocking 优先，blocking 后置）。
- `docs/TESTING.md`：补充 Webhook 协议测试规划（设计）。
- `CHANGELOG.md`：补充 v1.7.3 文档拆解与官方示例插件方案记录。

## 本轮明确的优先级

第一优先级不是 blocking Hook。第一优先级是：

1. non_blocking delivery
2. Webhook delivery 记录
3. 重试队列
4. 熔断机制
5. 审计记录
6. 后台治理入口
7. 官方示例插件端到端验证方案

## 本轮不做

- 不实现真实 Webhook 投递代码。
- 不实现插件回调 Core API token。
- 不做 blocking Hook（明确后置）。
- 不执行第三方插件代码，不做 Go 动态加载，不运行外部 scripts，不加载 `.so/.dll/.node/wasm`。

## 下一阶段建议

- v1.7.4：Webhook non_blocking delivery 最小实现（event/delivery 记录 + 最小投递 + 最小审计 + 最小后台查看；不做 blocking、不做复杂重试、不做熔断）。
- v1.7.5：Webhook 重试队列与熔断机制（non_blocking）。
