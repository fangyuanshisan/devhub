# v1.7.4：Webhook non_blocking delivery 最小实现版

本轮任务：为 DevHub 的第三方插件运行模型（HTTP 插件服务 / Webhook）打下最小落地基础，仅覆盖 **non_blocking Webhook delivery** 的“记录 + 发送尝试 + 后台可见”闭环。

> 说明：本版本不实现 blocking Hook；不执行第三方插件代码；不做动态加载；不实现插件回调 Core API token/scopes。

## 范围

已实现（最小闭环）：

- Webhook 事件记录：`webhook_events`（event_id、plugin_code、hook_name、mode、payload/metadata、status 等）
- Webhook 投递记录：`webhook_deliveries`（delivery_id、event_id、target_url、status、response_status、error_message 等）
- non_blocking delivery 的发送尝试（失败不阻断 Core 主流程）
- 后台最小查看入口（用于观察 event/delivery 记录；不等价于“插件代码运行”）
- 基础审计与可追踪字段（actor/request_id 等按现有审计体系记录）

未实现 / 明确不做：

- delivery 失败重试队列（v1.7.5 才补齐）
- circuit breaker 熔断（v1.7.5 才补齐）
- HMAC 签名鉴权与 Secret 轮换（v1.7.6 才补齐）
- blocking Hook（后续阶段）
- 插件回调 Core API token/scopes（后续阶段）
- 第三方插件代码执行 / Go plugin 动态加载

## 本轮检查说明

本轮为实现任务，涉及后端与后台管理端改动，按最低检查要求应执行：

- `gofmt`
- `go test ./...`
- `go build`
- `cd web/admin-app && npm run build`

若受执行环境影响导致前端构建无法执行，需要在 `docs/TESTING.md` 中如实记录。
