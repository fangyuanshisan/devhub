# v1.8.0 Release Notes

主题：官方插件前端挂载模型与 iframe / sandbox 容器设计版

更新时间：2026-05-18

本版本为**文档设计与口径收口**任务，聚焦 DevHub 插件“前端挂载模型”的下一阶段路线：挂载点（slots）、iframe/sandbox 隔离策略、postMessage 通信协议与权限/状态控制边界。

重要说明：

- 本轮为文档设计任务，**未修改代码**，未执行测试、构建或 E2E。
- 本轮不实现 blocking Hook，不执行第三方不可信代码，不做远程动态加载，不做插件市场。

## 1. 本轮目标

1. 明确官方/第三方插件前端扩展的主方向：**iframe + sandbox + postMessage**。
2. 定义 DevHub 前端挂载点（后台/前台/版主工作台）与权限边界。
3. 明确插件页面受以下状态共同约束：
   - 插件全局 enabled/disabled/soft_uninstalled
   - community 插件 enabled/disabled
   - 当前用户权限（admin/moderator/user）
4. 明确 `official_announcement` 作为首个端到端验证插件的前端挂载方案（设计）。

## 2. 新增与更新文档

- 新增：`docs/PLUGIN_FRONTEND_MOUNT_MODEL.md`
  - slots 设计：`admin.sidebar.menu`、`admin.plugin.detail.tab`、`admin.dashboard.card`、`frontend.*`、`moderator.sidebar.menu`
  - iframe/sandbox 基线策略与能力最小化建议
  - postMessage 协议 envelope、握手、上下文与受控请求模型（设计口径）
  - 插件状态/权限 gating 规则（必须由服务端最终裁决）
  - `official_announcement` 前后台挂载验证方案（设计）

## 3. 已完成与未完成的边界

已完成（截至 v1.7.9）：

- Webhook non_blocking 链路（events/deliveries/retry/circuit/signature/secrets）治理与审计闭环。
- 插件服务回调 Core API 的最小通道（callback token + scopes + callback requests）。

设计中 / 未完成（v1.8.0 本轮仅输出设计）：

- 插件前端 slots 的真实渲染与宿主页面实现。
- iframe 容器与统一 postMessage Host 的真实落地（消息通道、allowlist、权限联动）。
- 插件前端配置写入（例如 `config.write`）的受控前端通道。

## 4. 下一步建议

- v1.8.1：官方公告插件前端挂载“最小实现”（Host 页面 + iframe 容器 + handshake/context + config.read + audit.write），仍不执行第三方不可信代码。
- v1.8.2：补齐权限矩阵与 community 插件状态联动的前端治理体验（灰态/占位/错误态）。
