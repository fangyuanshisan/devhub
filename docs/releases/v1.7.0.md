# DevHub v1.7.0

v1.7.0 定义为“远程插件包治理与安装安全增强版”。本阶段从远程插件包下载治理开始，逐步补齐远程包从只读索引到 staging、安全检查、预校验、依赖兼容、安装事务和启用前安全检查的受控链路。

## v1.7.0-P0-01：远程插件包下载到 staging 与下载安全校验

已完成：

- 新增远程插件包安全下载 API：`POST /api/v1/admin/plugins/packages/download`。
- 新增 staging 查询与删除 API：`GET /api/v1/admin/plugins/packages/staging`、`GET /api/v1/admin/plugins/packages/staging/:id`、`DELETE /api/v1/admin/plugins/packages/staging/:id`。
- 新增 `plugin_package_downloads` 记录模型，持久化下载状态、来源 URL、最终 URL、文件大小、sha256、content-type、staging 路径、错误码和错误信息。
- staging 目录为 `storage/plugins/staging/downloads/`；文件名不使用远程文件名，而由 `plugin_code`、`version`、sha256 前缀和时间戳生成。
- URL 安全限制：仅允许 HTTPS；拒绝 file/http/ftp/gopher、localhost、回环地址、内网地址、link-local 地址；DNS 解析和每次重定向后都会重新校验。
- 下载安全限制：最多 3 次重定向、连接 / TLS / 读取超时、默认 20MB 上限、仅允许 `.zip` / `.tar.gz` / `.tgz`。
- 下载后计算 sha256：匹配时状态为 `downloaded`；不匹配为 `checksum_failed` 并清理文件；未提供 sha256 时为 `checksum_missing`，只能保留 staging 等待人工确认。
- 后台“上传包管理”页新增最小远程下载表单和 staging 列表 / 删除入口。
- 审计动作：`plugin.package.download.requested`、`plugin.package.download.success`、`plugin.package.download.failed`、`plugin.package.download.rejected`、`plugin.package.checksum.failed`、`plugin.package.staging.deleted`。

未完成 / 不支持：

- 不安装、不启用、不自动解压安装、不执行插件代码、不运行 package scripts、不加载 Go plugin、不执行外部 SQL、不动态加载前端资产。
- 不做插件市场、远程更新、依赖安装、插件卸载、完整 sandbox。
- 本轮不新增签名验签能力；后续解压 / dry-run 阶段可复用既有签名机制。
- 没有 sha256 的包不能进入自动安装链路。

## v1.7.0-P0-05：插件启用前安全检查（enable-precheck）

已完成：

- 新增启用前检查记录模型：`plugin_enable_prechecks`，保存 `status`、`can_enable`、文件完整性/manifest/依赖/配置/迁移/权限/菜单/路由/Hook/content_type/runnable readiness 的结构化结果，以及 warnings/errors/summary。
- 新增 API：
  - `POST /api/v1/admin/plugins/:code/enable-precheck`
  - `GET /api/v1/admin/plugins/enable-prechecks`
  - `GET /api/v1/admin/plugins/enable-prechecks/:id`
  - `DELETE /api/v1/admin/plugins/enable-prechecks/:id`
- 启用前检查强制链路：只有存在最近一条 `plugin_package_prechecks(status=passed)` 且对应 `plugin_package_compat_checks(can_install=true)` 的插件才能执行 enable-precheck，避免跳过 staging 预检与兼容性检查。
- 文件完整性复检（`source_type=local_package`）：基于预检记录 `package_path` 重新扫描包文件、校验 checksums、读取 `manifest.json` 并与安装时 `manifest_checksum` 比对；发现危险文件、checksum 错误或 manifest 变更将阻断启用前检查。
- manifest 再校验：复用当前 manifest validate 规则并检查 Core 兼容范围；不兼容时阻断。
- 依赖/配置/迁移复检：复用现有依赖与配置校验、迁移状态检查（pending/failed 阻断），只做检查不执行迁移。
- 冲突复检：对 permissions/menus/routes/hooks/content_types 做声明冲突检查，防止覆盖敏感路径或越权声明。
- 后台插件详情「Readiness」页签增加最小入口：对 disabled 插件可点击“启用前检查”并展示 can_enable/status/warnings/errors，不提供真正启用按钮。
- 审计动作：`plugin.enable_precheck.requested`、`plugin.enable_precheck.success`、`plugin.enable_precheck.failed`、`plugin.enable_precheck.blocked`、`plugin.enable_precheck.config_invalid`、`plugin.enable_precheck.migration_pending`、`plugin.enable_precheck.file_integrity_failed`、`plugin.enable_precheck.deleted`。

边界：

- 本轮只做检查，不启用插件，不注册运行时，不开放前台/后台入口，不允许创建内容，不执行插件代码/脚本，不执行 migration。

测试记录：

- `go test ./...`：通过（新增 `internal/service/plugin_enable_precheck_test.go` 覆盖基础链路与审计）。

## v1.7.0-P0-06：插件启用与运行时注册（enable）

已完成：

- 新增启用任务记录：`plugin_enable_tasks`，记录 `previous_status/new_status`、注册摘要、effective_config 快照、errors/warnings 与审计链路。
- 新增 API：
  - `POST /api/v1/admin/plugins/enable-prechecks/:id/enable`
  - `GET /api/v1/admin/plugins/enable-tasks`
  - `GET /api/v1/admin/plugins/enable-tasks/:id`
  - `POST /api/v1/admin/plugins/enable-tasks/:id/retry`
  - `DELETE /api/v1/admin/plugins/enable-tasks/:id`
- 启用输入强约束：仅允许最新 enable-precheck `status=passed|warning` 且 `can_enable=true` 的插件启用；启用前做 TOCTOU 快速复检（配置/依赖/迁移/content_type 冲突等），本轮策略：`pending migrations` 阻断启用。
- enable-precheck TTL：默认 600 秒（`DEVHUB_PLUGIN_ENABLE_PRECHECK_TTL_SECONDS`；设置为 0 可禁用 TTL 校验）。
- 启用成功后插件状态为 `enabled`；平台治理能力通过 DB-as-source 生效：
  - 内容类型创建校验与发布入口能识别插件声明的 `content_type_definitions`。
  - 菜单与入口展示会按插件状态与权限规则显示。
  - HookBus 会触发 `AfterPluginEnabled`（non-blocking）。
- 后台插件详情 Readiness 页签：enable-precheck 结果为 `can_enable=true` 时显示“启用（基于检查结果）”按钮，启用后刷新插件状态。
- 审计动作：`plugin.enable.requested/started/success/failed/retry`、`plugin.runtime.registered`。

边界：

- 启用不执行插件包内代码、不运行 package scripts、不加载 Go plugin、不自动执行 migration、不自动为所有子站启用。

测试记录：

- `docker run --rm ... go test ./...`：通过（新增 `internal/service/plugin_enable_task_test.go` 覆盖 enable-precheck TTL 与基础启用链路）。

## v1.7.0-P0-07：插件软卸载（soft uninstall）

已完成：

- 新增软卸载任务记录：`plugin_uninstall_tasks`，用于记录 soft uninstall 的发起人、状态流转、影响范围摘要、依赖阻断结果、运行时注销摘要、errors/warnings 与审计链路。
- 新增 API：
  - `GET /api/v1/admin/plugins/:code/uninstall-impact`：软卸载影响分析（复用 impact 计数 + 依赖阻断预检）。
  - `POST /api/v1/admin/plugins/:code/soft-uninstall`：执行软卸载（归档），并写入 uninstall task 记录。
  - `GET /api/v1/admin/plugins/uninstall-tasks`、`GET /api/v1/admin/plugins/uninstall-tasks/:id`、`POST /api/v1/admin/plugins/uninstall-tasks/:id/retry`、`DELETE /api/v1/admin/plugins/uninstall-tasks/:id`。
- 依赖阻断：若存在 **enabled** 插件对目标插件声明 `required=true` 依赖，则阻断软卸载并返回明确错误，错误中包含依赖插件列表；仅 optional 依赖存在时只产生 warning。
- 运行时注销：软卸载将插件全局状态置为 `archived`，平台运行时治理以状态为源实现“入口/创建链路失效”：
  - `content_type` 新建强校验会被阻断（归档插件不可新建内容、子站不可启用）。
  - 菜单/入口展示会因插件状态不再为 enabled 而自动隐藏。
  - HookBus 通过插件状态 gating 不再执行 archived 插件 hook（并触发 `AfterPluginDisabled` non-blocking）。
- 后台插件详情（Readiness Tab）新增“软卸载（归档）”最小入口：填写原因 -> 展示影响摘要 -> 确认 -> 执行。
- 审计动作：
  - `plugin.soft_uninstall.requested/started/success/failed/retry/deleted`
  - `plugin.runtime.unregistered`

边界：

- 仅软卸载：不做硬卸载；不删除插件安装记录、不删除文件、不删除配置、不删除迁移记录、不删除审计日志、不删除历史内容；不执行 migration down；不执行插件代码/脚本；不加载 Go plugin。
- 历史内容与 SEO：软卸载后历史内容详情仍可访问；`/topics/:id`、`/c/:slug` SEO 不受影响；仅阻断新建入口与运行时治理入口。

测试记录：

- `go test ./...`：通过（新增 `internal/service/plugin_soft_uninstall_test.go` 覆盖依赖阻断与任务记录/审计）。

## v1.7.0-P0-08：插件升级流程（compat-check 驱动）

已完成：

- 新增升级任务记录：`plugin_upgrade_tasks`，用于记录基于 `compat-check(can_install=true)` 的升级执行与审计（不会自动启用，不执行 migration）。
- 新增 API：
  - `GET /api/v1/admin/plugins/:code/upgrade-impact?target_compat_check_id=...`：升级影响分析与 manifest diff 摘要。
  - `POST /api/v1/admin/plugins/:code/upgrade-from-package`：基于目标 `compat_check_id` 执行升级并生成任务记录。
  - `GET /api/v1/admin/plugins/upgrade-tasks`、`GET /api/v1/admin/plugins/upgrade-tasks/:id`、`POST /api/v1/admin/plugins/upgrade-tasks/:id/retry`、`DELETE /api/v1/admin/plugins/upgrade-tasks/:id`。
- 升级输入强约束：
  - 仅允许同 `plugin_code` 的更高版本升级（不支持降级、不同 code 升级）。
  - 目标包必须 `precheck.status=passed`、`compat-check.can_install=true`。
  - 目标包若来自 staging 下载，必须 `download.status=downloaded` 且 `sha256_expected == sha256_actual`；`checksum_missing` 默认禁止进入升级流程。
- 升级执行边界：
  - 升级前会对目标包重新执行 dry-run（scan/checksum/risk/manifest validate/install preview），危险文件/blocked 风险/ checksum mismatch 会阻断升级。
  - 升级本轮不执行 migration；如果目标版本声明 migrations，升级后插件会进入 `migration_pending`（否则 `disabled`）。
  - 升级后默认不自动启用；需要管理员重新执行 enable-precheck + enable。
- 审计动作：`plugin.upgrade.impact.viewed`、`plugin.upgrade.requested/started/success/failed`。

限制：

- 当前升级实现仍以“治理层 manifest 升级”为主，不做独立 installed filesystem snapshot 切换；后续如实现独立 `installed/{code}/{version}` 目录，需要补齐文件侧回滚与 active_version 指针。
- 本轮未实现升级任务 rollback API（仅保留任务记录与失败可重试）。

测试记录：

- `go test ./...`：通过（新增 `internal/service/plugin_upgrade_task_test.go` 覆盖 system 禁止升级、code mismatch、低/同版本拒绝、precheck 未通过、compat-check 不可安装等规则）。
- 后台最小入口：插件详情抽屉（Readiness Tab）新增“升级（基于 compat-check）”最小面板（impact 预览 + 执行 + 任务列表/重试）；需后续补完整独立升级页与 E2E。
