# DevHub v1.7.0

v1.7.0 定义为“远程插件包治理与安装安全增强版”。本阶段从远程插件包下载治理开始，逐步补齐远程包从只读索引到 staging、安全检查、预校验、依赖兼容、安装事务和启用前安全检查的受控链路。

## v1.7.0-P0-01：远程插件包下载到 staging 与下载安全校验

已完成：

- 新增远程插件包安全下载 API：`POST /api/v1/admin/plugins/packages/download`。
- 新增 staging 查询与删除 API：`GET /api/v1/admin/plugins/packages/staging`、`GET /api/v1/admin/plugins/packages/staging/:id`、`DELETE /api/v1/admin/plugins/packages/staging/:id`。
- 新增 `plugin_package_downloads` 记录模型，持久化下载状态、来源 URL、最终 URL、文件大小、sha256、content-type、staging 路径、错误码和错误信息。
- staging 目录为 `storage/plugins/staging/downloads/`；文件名不使用远程文件名，而由 `plugin_code`、`version`、sha256 前缀和时间戳生成。
- URL 安全限制：仅允许 HTTPS；拒绝 file/http/ftp/gopher、localhost、回环地址、内网地址、link-local 地址；DNS 解析和每次重定向后都会重新校验。
- 下载安全限制：最多 3 次重定向、连接 / TLS / 读取超时、默认 20MB 上限、仅允许 `.zip` / `.tar.gz` / `.tgz`。
- 下载后计算 sha256：匹配时状态为 `downloaded`；不匹配为 `checksum_failed` 并清理文件；未提供 sha256 时为 `checksum_missing`，只能保留 staging 等待人工确认。
- 后台“上传包管理”页新增最小远程下载表单和 staging 列表 / 删除入口。
- 审计动作：`plugin.package.download.requested`、`plugin.package.download.success`、`plugin.package.download.failed`、`plugin.package.download.rejected`、`plugin.package.checksum.failed`、`plugin.package.staging.deleted`。

未完成 / 不支持：

- 不安装、不启用、不自动解压安装、不执行插件代码、不运行 package scripts、不加载 Go plugin、不执行外部 SQL、不动态加载前端资产。
- 不做插件市场、远程更新、依赖安装、插件卸载、完整 sandbox。
- 本轮不新增签名验签能力；后续解压 / dry-run 阶段可复用既有签名机制。
- 没有 sha256 的包不能进入自动安装链路。

## v1.7.0-P0-03：插件依赖 / 兼容性检查

已完成：

- 新增 `plugin_package_prechecks` 最小持久化模型，作为 compat-check 的强制输入来源；只有 `status=passed` 的预检记录可以继续。
- 新增 `plugin_package_compat_checks` 记录模型，保存 Core 兼容、依赖、冲突、权限、菜单、路由、Hook、config_schema、migration、warnings、errors、summary 与 `can_install`。
- 新增 API：`POST /api/v1/admin/plugins/packages/prechecks/:id/compat-check`、`GET /api/v1/admin/plugins/packages/compat-checks`、`GET /api/v1/admin/plugins/packages/compat-checks/:id`、`DELETE /api/v1/admin/plugins/packages/compat-checks/:id`。
- Core 兼容检查支持精确版本、比较范围、`^x.y.z`、`~x.y.z`，当前 Core 来自 `VERSION`。
- 依赖检查支持字符串数组、对象数组和 `{ "plugins": [...] }`；required 依赖缺失 / 版本不满足阻断，optional 缺失仅 warning。
- 增加 plugin_code、content_type、permission、menu、route、Hook、config_schema、migration 兼容性检查，并由后端计算 `can_install`。
- 后台“上传包管理”页增加最小兼容性检查表单和结果列表，只展示检查结论，不提供安装 / 启用按钮。
- 审计动作：`plugin.package.compat_check.requested/success/failed/incompatible/dependency_missing/conflict_detected/deleted`。

边界：

- 本轮只做安装前依赖 / 兼容性检查，不安装、不启用、不注册权限 / 菜单 / 路由 / Hook、不执行 migration、不执行插件代码、不运行脚本、不加载 Go plugin、不自动下载依赖。
- 完整 P0-02 解压预检 UI 不是本轮目标；本轮只补齐 compat-check 所需的预检记录来源模型。

## v1.7.0-P0-05：插件启用前安全检查（enable-precheck）

已完成：

- 新增启用前检查记录模型：`plugin_enable_prechecks`，保存 `status`、`can_enable`、文件完整性/manifest/依赖/配置/迁移/权限/菜单/路由/Hook/content_type/runnable readiness 的结构化结果，以及 warnings/errors/summary。
- 新增 API：
  - `POST /api/v1/admin/plugins/:code/enable-precheck`
  - `GET /api/v1/admin/plugins/enable-prechecks`
  - `GET /api/v1/admin/plugins/enable-prechecks/:id`
  - `DELETE /api/v1/admin/plugins/enable-prechecks/:id`
- 启用前检查强制链路：只有存在最近一条 `plugin_package_prechecks(status=passed)` 且对应 `plugin_package_compat_checks(can_install=true)` 的插件才能执行 enable-precheck，避免跳过 staging 预检与兼容性检查。
- 文件完整性复检（`source_type=local_package`）：基于预检记录 `package_path` 重新扫描包文件、校验 checksums、读取 `manifest.json` 并与安装时 `manifest_checksum` 比对；发现危险文件、checksum 错误或 manifest 变更将阻断启用前检查。
- manifest 再校验：复用当前 manifest validate 规则并检查 Core 兼容范围；不兼容时阻断。
- 依赖/配置/迁移复检：复用现有依赖与配置校验、迁移状态检查（pending/failed 阻断），只做检查不执行迁移。
- 冲突复检：对 permissions/menus/routes/hooks/content_types 做声明冲突检查，防止覆盖敏感路径或越权声明。
- 后台插件详情「Readiness」页签增加最小入口：对 disabled 插件可点击“启用前检查”并展示 can_enable/status/warnings/errors，不提供真正启用按钮。
- 审计动作：`plugin.enable_precheck.requested`、`plugin.enable_precheck.success`、`plugin.enable_precheck.failed`、`plugin.enable_precheck.blocked`、`plugin.enable_precheck.config_invalid`、`plugin.enable_precheck.migration_pending`、`plugin.enable_precheck.file_integrity_failed`、`plugin.enable_precheck.deleted`。

边界：

- 本轮只做检查，不启用插件，不注册运行时，不开放前台/后台入口，不允许创建内容，不执行插件代码/脚本，不执行 migration。
