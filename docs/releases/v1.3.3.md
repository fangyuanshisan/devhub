# DevHub v1.3.3 Release Notes

定位：插件平台治理收口版（Plugin Platform Governance Closure）

本版本目标是在 v1.3.2 已铺好的插件状态、配置、HookBus、迁移、影响分析、审计和后台治理中心基础上，进一步收口当前内置插件平台的真实能力边界，补齐插件启用 readiness 检查，并统一文档口径。

## 基线口径

v1.3.3 当前仍是内置系统插件平台，不是第三方插件市场、插件包上传、远程安装或 Go 动态插件加载系统。

当前真实表名仍是 `topics` 与 `categories`；`contents` / `channels` 只作为架构概念或长期目标命名。

## 本版本完成

### 插件生命周期状态收口

- `plugins.status` 当前接受：`discovered`、`installed`、`migrated`、`configured`、`enabled`、`disabled`、`running`、`config_invalid`、`migration_pending`、`dependency_missing`。
- 当前发布可用性仍只认 `enabled`；除 `enabled` 以外的状态都不会放行新建插件内容。
- 新增 Service 层插件启用 readiness 检查：全局启用和子站启用都会先校验插件存在、全局配置有效、依赖插件已启用、没有失败迁移。
- 当前内置迁移仍是 up/no-op 记录型迁移；`pending` migration 会通过健康状态和迁移 Tab 提示，但不阻断启用，避免内置插件被未手动确认的 no-op 迁移卡死。
- `failed` migration 会阻断全局启用和子站启用，要求先重试或处理迁移错误。

### config_schema 后端强校验确认

- 全局插件配置与子站插件配置保存时均执行后端校验。
- 简化 schema 支持：`type`、`properties`、`required`、`enum`、`object`、`boolean`、`string`、`number`、`integer`、`array/items`、`min/max`、`default`、`additionalProperties`。
- 后台 Ajv 校验只是前端体验，不能替代后端校验。
- 配置审计继续写入 `old_value`、`new_value` 和 `metadata_json.changed_keys`。
- 配置合并顺序：`config_schema` 默认值 < `plugins.config_json` 全局配置 < `community_plugins.config_json` 子站覆盖配置，API 通过 `resolved_config.default/global/community/effective` 表达。

### HookBus 接入与观测收口

- HookBus 当前服务内置系统插件，不支持第三方动态 Hook、远程 Hook 或 Webhook。
- 已接入并可记录的核心 Hook：`BeforeCreateContent`、`AfterCreateContent`、`BeforeUpdateContent`、`AfterUpdateContent`、`BeforeModerateContent`、`AfterModerateContent`、`AfterCreateComment`、`OnSearchIndex`、`OnNotificationBuild`、`OnSEOBuild`、`AfterPluginEnabled`、`AfterPluginDisabled`。
- blocking Hook 失败会阻断主流程，并写入 `hook_executions` 与 `plugin.hook.blocked` 审计。
- non-blocking Hook 失败不会阻断主流程，但会写入 `hook_executions` 与 `plugin.hook.failed` 审计。
- 后台 Hooks Tab 展示声明 Hook、平台调用点、handler 状态、执行次数、失败次数、平均耗时、最近执行、最近失败和最近错误；无法静态判断真实 handler 的地方不伪造。

### 插件迁移闭环口径收口

- `plugin_migrations` 可查询内置插件迁移声明和执行记录。
- 插件详情迁移 Tab 展示 migration name、version、direction、status、executed/finished time、duration、error、rollback 标识。
- 已 success 的 migration 不重复执行；failed migration 可以 retry。
- 迁移执行写入 `plugin.migration.run`、`plugin.migration.retry`、`plugin.migration.success`、`plugin.migration.failed` 审计。
- 当前 runner 是内置 up/no-op 记录型 runner：主 schema / 启动迁移负责建表，`plugin_migrations` 负责记录插件迁移状态；真正独立 Migration Runner、migration down、硬回滚和迁移前备份仍是后续能力。

### 插件权限矩阵口径收口

- 内容创建权限来自 `ContentTypeDefinition.create_permission`：`qa.question.create`、`docs.document.create`、`wiki.page.create`、`projects.project.create`、`jobs.job.create`、`ai_works.work.create`、`core.topic.create`。
- `post.create` 仅作为 `core.topic.create` 的历史兼容桥，不是长期主权限。
- `POST /api/v1/admin/posts` 创建内容时叠加对应插件 create 权限；普通前台 token 不能访问后台插件治理 API。
- 版主插件菜单按全局状态、子站状态、community scope 和权限过滤。
- 后台插件详情权限 Tab 展示权限码、作用域和说明。

### 后台插件治理中心收口

- `/admin-next/plugins` 已具备插件列表、统计卡片、筛选、详情 Tabs、配置、Hooks、路由、影响范围、审计、迁移和运行状态视图。
- JSON 配置编辑、非法 JSON 拦截、schema 错误展示、子站插件配置、全局 disabled 不能在子站启用、禁用前影响分析均已接入。
- 审计 Tab 使用真实审计接口，不伪造结构化字段；旧日志结构化不完整时按空值展示。
- 禁用插件不影响历史内容访问和 `/topics/:id` SEO 动态 HTML。

## 本版本当前限制

- 生命周期状态枚举已完整进入 schema / Store，但尚未形成自动状态机；`running`、`configured`、`migrated` 等仍是可记录状态，不等于自动流转。
- `pending` migration 在当前内置 no-op 阶段不阻断启用；未来独立 Migration Runner 阶段可调整为严格阻断策略。
- HookBus 只服务内置系统插件；没有第三方 Hook、远程 Hook、Webhook、动态加载、沙箱或异步队列。
- config_schema 是简化实现，不覆盖完整 JSON Schema；自动表单、深层 diff、配置版本和回滚仍待后续。
- 插件迁移仍不支持 migration down、真实 rollback、迁移前备份、复杂依赖排序和外部插件迁移包。
- 权限矩阵仍是最小权限码闭环；完整 RBAC 配置 UI、按 community/category 作用域分配和更细错误码仍待后续。
- Projects / Jobs / AI Works 已接入插件平台治理，但专属扩展表、专属搜索、通知、SEO 和业务闭环仍待后续。
