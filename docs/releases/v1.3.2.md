# DevHub v1.3.2 Release Notes

定位：插件平台治理增强版（Plugin Platform Governance Enhancements）

本版本目标是把 DevHub 从“插件平台雏形”推进到“可治理的插件平台”，重点增强 HookBus 真实执行、配置 schema 校验、结构化审计、权限矩阵与插件迁移闭环等平台能力。

## 基线口径

v1.3.2 当前仍是内置系统插件平台，不是第三方插件市场、插件包上传、远程安装或 Go 动态插件加载系统。

真实状态以代码中的 `plugins.status`、`community_plugins.status`、`topics.plugin_code`、`categories.plugin_code`、`categories.allowed_content_types`、`admin_logs` 和 `plugin_migrations` 为准。`plugins.status` 已支持 `discovered`、`installed`、`migrated`、`configured`、`enabled`、`disabled`、`running`、`config_invalid`、`migration_pending`、`dependency_missing`，但当前发布可用性仍只认 `enabled`；完整自动生命周期状态机、插件安装器和插件市场仍是下一阶段路线图能力。

当前真实表名仍是 `topics` 与 `categories`；`contents` / `channels` 只作为架构概念或长期目标命名。

## 本版本完成

### HookBus 真实执行（内置插件）

- 将 HookBus 抽象为插件平台能力：`internal/plugins/hookbus.go`。
- 在核心业务流程中接入 Hook 调度：
  - `BeforeCreateContent`（blocking）
  - `AfterCreateContent`（non-blocking）
  - `BeforeUpdateContent`（blocking）
  - `AfterUpdateContent`（non-blocking）
  - `BeforeModerateContent` / `AfterModerateContent`（用于删除/治理动作的最小接入）
  - `AfterCreateComment`（non-blocking）
  - `OnSEOBuild` / `OnSearchIndex` / `OnNotificationBuild`（non-blocking）
- 内置插件 Hook 示例接入：
  - qa/docs/wiki 以最小 handler 方式注册（`internal/plugins/hook_handlers.go`）。
- 新增 `hook_executions` 执行记录表，记录 Hook 名称、插件、模式、内容、子站、操作者、耗时、成功/失败、错误和 metadata。
- blocking hook 失败会阻断主流程，并写入 `plugin.hook.blocked` 审计。
- non-blocking hook 失败不阻断主流程，但会写入 `plugin.hook.failed` 审计。
- 新增后台 Hook 统计接口：`GET /api/v1/admin/plugins/:code/hooks`，用于返回执行次数、失败次数、平均耗时、最近执行、最近失败、最近错误和最近执行记录。
- 插件详情 Hooks Tab 已接入运行时统计与最近执行记录，不再只展示 manifest 声明。

### config_schema 真实校验

- 新增简化 schema 校验器：`internal/plugins/configschema.go`。
- 全局插件配置与子站插件配置保存时都会校验：
  - `plugins.config_json`
  - `community_plugins.config_json`
- 校验策略（简化 JSON Schema）：
  - 支持 `type/properties/required/enum/min/max/items/additionalProperties/default` 的最小集合。
  - 默认拒绝未知字段（除非显式 `additionalProperties=true`）。
- `config_schema.properties.*.default` 已纳入 `resolved_config.effective`，配置合并顺序为 schema 默认值 < 全局配置 < 子站配置。
- 配置审计 metadata 增加 `changed_keys`，记录本次变更的顶层配置键。

### 结构化审计（admin_logs）

- admin_logs 已支持结构化字段（JSON 类型）：
  - `old_value`
  - `new_value`
  - `metadata_json`
- 插件治理相关接口通过 `auditStructured` 写入结构化审计：
  - 全局插件启用/禁用
  - 全局插件配置更新
  - 子站插件启用/禁用
  - 子站插件配置更新
  - 子站插件排序
  - Hook 失败 / 阻断
  - 带 `plugin_code` 的插件内容治理操作，如隐藏/恢复、置顶、加精和评论治理
- 新增插件专用审计查询入口：`GET /api/v1/admin/plugins/:code/audit-logs`。

### 插件健康状态与后台治理中心

- `GET /api/v1/admin/plugins` 返回轻量 `health` 摘要。
- 健康状态来源：
  - 插件全局状态。
  - `config_schema` 对 `plugins.config_json` 的校验结果。
  - `plugin_migrations` 的 pending / failed 记录。
  - Hook 失败统计与最近错误。
  - 依赖插件是否启用。
- 当前健康状态包括 `healthy`、`warning`、`error`、`disabled`、`migration_pending`、`config_invalid` 和 `dependency_missing`。
- 后台插件列表展示运行健康、配置状态、迁移状态、Hook 状态、最近错误和建议操作。
- 插件详情抽屉新增“运行状态”Tab，并将“审计”Tab 接入插件专用审计接口。

### 插件迁移闭环（platform-level）

- 新增 `plugin_migrations` 表用于记录插件迁移执行状态。
- 新装库（`db/mysql/001_schema.sql`）与升级迁移（`db/mysql/migrations/008_plugin_migrations.sql`）结构一致。
- 内置插件声明 migration：
  - qa：`qa_questions`、`qa_answers`
  - docs：`docs_spaces`、`docs_documents`
  - wiki：`wiki_spaces`、`wiki_pages`、`wiki_page_versions`
- 新增迁移查询、执行和重试 API：
  - `GET /api/v1/admin/plugins/:code/migrations`
  - `POST /api/v1/admin/plugins/:code/migrations/run`
  - `POST /api/v1/admin/plugins/:code/migrations/:name/retry`
- 第一阶段 runner 只支持内置插件 up/no-op 迁移：表结构由主 schema 和启动迁移保证，runner 负责记录 running / success / failed、耗时和错误，不会重复破坏数据。
- 迁移操作写入 `plugin.migration.run`、`plugin.migration.retry`、`plugin.migration.success`、`plugin.migration.failed` 审计。
- 后台插件详情新增“迁移”Tab，可查看状态、最近执行、失败原因、rollback 标识，并执行/重试迁移。

### 插件状态模型与禁用影响分析

- 扩展 `plugins.status` 枚举，MemoryStore、MySQLStore、新装 schema 和老库迁移均支持插件治理状态模型。
- `ValidateTopicPluginAccess` 继续作为内容创建强校验入口：只有全局 `enabled` 且当前子站 `enabled` 的插件才能创建对应 `content_type`。
- 全局禁用或设置为 `config_invalid` / `migration_pending` 等非 enabled 状态后，后端强传对应 `content_type` 会被拒绝；历史内容详情页和 SEO 不受影响。
- impact API 增强为更完整的计数视图：历史内容、启用/禁用子站、绑定板块、近 7 天内容、审核中内容、菜单声明、配置覆盖和待执行迁移。
- 后台全局禁用和子站禁用确认会展示 impact 计数；`recent_hook_errors_count` 已接入 `hook_executions` 最近 7 天失败记录。

### 后台 E2E Docker Runner

- 新增 `admin-e2e` Docker Compose 服务，固定使用 `mcr.microsoft.com/playwright:v1.59.1-noble`。
- 后台 Playwright 依赖在镜像构建阶段通过 `npm ci` 安装，运行 E2E 时复用项目内镜像，不依赖宿主机 Node/npm。
- 当前最小 E2E 覆盖插件治理中心核心路径：插件列表、详情 Tabs、JSON Editor/Ajv 错误提示、全局禁用确认、子站插件抽屉和 PluginContent 入口。
- 新增 `frontend-e2e` Docker Compose 服务，前台 Playwright 依赖同样在镜像构建阶段安装并复用本地镜像。
- 后台 E2E 已从插件治理中心 5 条扩展到 11 条，新增后台登录、内容管理、评论管理、子站管理、标签管理和审计日志冒烟。
- 前台 E2E 新增 6 条冒烟用例，覆盖首页、子站页、搜索页、Topic 动态详情、未登录发布拦截和标签页。

## 本版本当前限制

- HookBus 本版本只覆盖“内置系统插件”，不包含第三方动态插件执行环境。
- HookBus 当前已有统一执行记录表、失败统计、最近错误、平均耗时、失败审计和轻量健康摘要；但尚未提供告警、重试策略或异步队列。
- 插件状态枚举已扩展，但 `discovered -> installed -> migrated -> configured -> enabled -> running` 的自动流转状态机尚未完成；当前治理仍以手动 `plugins.status` 与 `community_plugins.status` 判断为主。
- config_schema 为简化实现，不覆盖完整 JSON Schema 规范；复杂规则需要后续增强。
- 配置 diff 当前为顶层 `changed_keys`，不支持深层路径级 diff、配置版本回滚或灰度发布。
- 插件迁移 runner 当前只支持内置插件 up/no-op 执行记录和重试；migration down、真实 rollback、迁移前备份、外部插件迁移包和复杂依赖排序仍是后续任务。
- impact API 仍是轻量计数，不返回受影响对象明细；`recent_hook_errors_count` 只代表近 7 天 Hook 失败次数。
- 插件健康状态是后台治理摘要，不等于完整监控系统；尚无独立健康 API、告警规则或自动恢复。
- 当前 E2E 仍是第一阶段核心冒烟矩阵，不覆盖多浏览器、多账号、前台登录互动、发布成功、插件启停联动和版主工作台完整矩阵。

## 后续计划（v1.3.x）

- 增强 HookBus 告警和重试策略。
- 增强 config_schema 校验能力与后台配置编辑体验（按 schema 提示/半自动表单）。
- 增强插件迁移治理：补 migration down / rollback 规划、迁移前备份、复杂依赖排序和失败重试体验。
