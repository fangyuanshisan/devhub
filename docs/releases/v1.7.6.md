# v1.7.6：Webhook 签名鉴权与 Secret 轮换增强版

本轮任务：在 `v1.7.5` 的 Webhook non_blocking delivery、重试队列与熔断机制基础上，补齐 **Webhook 请求签名鉴权** 与 **Secret 管理/轮换**，并打通最小后台治理入口与审计闭环。

> 说明：本轮为实现任务，包含后端与后台管理端改动。  
> 仍然不执行第三方插件代码，不做动态加载，不做 blocking Hook，不做插件回调 Core API token/scopes。

## 已实现

- DevHub 发送 Webhook 请求时使用 **HMAC-SHA256** 生成签名（发送端签名落地）
- 标准签名 Headers（发送端）：
  - `X-DevHub-Event-ID`
  - `X-DevHub-Delivery-ID`
  - `X-DevHub-Plugin-Code`
  - `X-DevHub-Timestamp`
  - `X-DevHub-Signature`（`v1=<hex>`）
  - `X-DevHub-Signature-Alg`（`HMAC-SHA256`）
  - `X-DevHub-Idempotency-Key`
  - `X-DevHub-Request-ID`
  - `X-DevHub-Body-SHA256`
  - `X-DevHub-Secret-Ref`
- signing string 规则：
  - `timestamp + "." + method + "." + path + "." + body_sha256`
- delivery 记录新增签名元信息（不含 Secret 明文）：
  - `signature_alg / secret_ref / body_sha256 / signature_status / signed_at / signature_error`
- Webhook Secret 管理（后台管理端）：
  - 创建 / 禁用 / 吊销 / 轮换
  - active / previous + grace window（默认 24h）
  - Secret 明文仅在创建/轮换响应中返回一次
- Admin API：
  - `GET /api/v1/admin/plugins/webhooks/secrets`
  - `GET /api/v1/admin/plugins/webhooks/secrets/:id`
  - `POST /api/v1/admin/plugins/webhooks/secrets`
  - `POST /api/v1/admin/plugins/webhooks/secrets/:id/rotate`
  - `POST /api/v1/admin/plugins/webhooks/secrets/:id/disable`
  - `POST /api/v1/admin/plugins/webhooks/secrets/:id/enable`
  - `POST /api/v1/admin/plugins/webhooks/secrets/:id/revoke`
- 后台最小 UI：
  - 插件 → 运行时治理 → Webhook 治理（页内 Tabs 增加 Secrets）
  - 创建/轮换弹窗展示 Secret 明文一次（关闭后不可再查看）
- 审计接入：
  - Secret 创建/轮换/禁用/恢复/吊销/过期 等 action

## 关键边界与联动规则

- **仅 non_blocking**：签名失败/Secret 缺失等不会阻断 Core 主流程（只影响该 delivery 的投递结果）。
- Secret 异常（missing/disabled/revoked/expired）：
  - 不发送请求
  - delivery 标记 `failed`
  - 不进入重试队列
- 远端 `401/403`：
  - 默认不重试（避免无意义打爆与安全风险）
- Secret 存储：
  - 入库为密文（复用 `DEVHUB_PLUGIN_CONFIG_KEYS` 的 keyring 加密）
  - 列表/详情 API 不返回密文与明文
  - 明文不会写入审计/日志/delivery
