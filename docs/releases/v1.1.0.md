# DevHub v1.1.0 - 子站模块增强版

[返回文档大纲](../README.md)

发布日期：2026-05-09

## 版本定位

DevHub v1.1.0 是“子站模块增强版”。本版本将 PHP、Go、Java、AI、Frontend 等子站从“内容筛选维度”升级为具备独立首页、独立 SEO、独立配置、独立板块、独立版主、独立统计、关注和公告能力的社区空间。

前台入口仍为 `/`，后台入口仍为 `/admin-next`，默认端口仍为 `8090`。`/topics/:id` 继续由 Go 动态输出百度 SEO HTML，没有改成纯 CSR。

## 背景

DevHub v1.0.0 已完成首个可运行社区 CMS 基线，包括 Topic、搜索、评论、问答采纳、互动、通知、举报、治理、admin-next、MemoryStore / MySQLStore 和 `/topics/:id` 百度 SEO 动态详情页。v1.1.0 在此基础上强化子站模块。

## 本版本目标

将子站从“内容筛选维度”升级为“独立社区空间”。子站应具备：

- 独立首页。
- 独立 SEO。
- 独立配置。
- 独立板块。
- 独立版主。
- 独立统计。
- 独立关注能力。
- 独立公告和基础运营配置。

## 本版本范围

本版本围绕 `communities`、`categories`、子站前台页、子站后台管理、子站 SEO、子站关注、子站统计和 sitemap 收录展开。不改变 DevHub 的项目名称、默认端口、前后台入口和 `sites/posts` 兼容 API。

## 本版本不做什么

- 标签合并。
- 标签别名。
- 标签趋势统计。
- 推荐算法。
- 声望积分。
- 复杂运营分析。
- 评论点赞。
- 取消已解决状态。

## 主要能力

- 子站资料增强：logo、cover image、slogan、theme color、SEO 字段、统计字段、hot score 和公告字段。
- 子站动态 SEO 页：`/c/:slug/` 由 Go 输出 title、description、canonical、h1、子站简介、板块链接、Topic 链接、标签链接、版主和公告。
- 兼容入口：`/site/:slug` 301 跳转到 canonical `/c/:slug/`。
- 子站统计：`GET /api/v1/communities/:slug/stats` 返回主题、评论、问答、未解决、关注、今日新增、版主和热度。
- 子站版主展示：`GET /api/v1/communities/:slug/moderators` 返回启用版主，前台子站页展示。
- 子站关注增强：复用 `POST /api/v1/follows/toggle`，`target_type=community` 会更新 follower_count 并写入动态。
- 子站后台管理：`/admin-next/communities` 支持新增、编辑、启用 / 禁用、排序、SEO、公告、前台跳转和版主管理跳转。
- 子站板块管理：后台支持查看、新增、编辑、启用 / 禁用、排序、导航展示、发帖开关和 SEO 字段。
- sitemap：动态包含启用子站 `/c/php/`、`/c/go/`、`/c/java/`、`/c/ai/`、`/c/frontend/`，禁用或归档子站不进入 sitemap。

## 数据结构计划

`communities` 增强字段：

- `logo`
- `cover_image`
- `slogan`
- `theme_color`
- `seo_title`
- `seo_description`
- `seo_keywords`
- `sort_order`
- `status`
- `follower_count`
- `topic_count`
- `comment_count`
- `hot_score`
- `announcement_title`
- `announcement_content`
- `announcement_url`

`categories` 增强字段：

- `nav_visible`
- `postable`
- `seo_title`
- `seo_description`
- `status`

MemoryStore 和 MySQLStore 均需要支持上述字段。MySQL 新库可直接使用 `db/mysql/001_schema.sql`，旧库启动时由现有补字段逻辑尽量自动补齐 v1.1.0 需要的列；生产环境仍建议先在预发库执行并验证。

## API 计划

新增或增强的公开接口：

```http
GET /api/v1/communities/:slug/stats
GET /api/v1/communities/:slug/moderators
POST /api/v1/follows/toggle
```

新增后台接口：

```http
GET  /api/v1/admin/communities
POST /api/v1/admin/communities
GET  /api/v1/admin/communities/:id
PUT  /api/v1/admin/communities/:id
POST /api/v1/admin/communities/:id/enable
POST /api/v1/admin/communities/:id/disable
POST /api/v1/admin/communities/reorder
GET  /api/v1/admin/communities/:id/categories
POST /api/v1/admin/communities/:id/categories
PUT  /api/v1/admin/categories/:id
POST /api/v1/admin/categories/:id/enable
POST /api/v1/admin/categories/:id/disable
POST /api/v1/admin/categories/reorder
```

后台接口需要 `Authorization: Bearer <access_token>`，并继续使用 admin RBAC 和子站范围权限。`sites/posts` 兼容 API 保持不变。

## 前台计划

- `/c/:slug/` 展示子站首页。
- `/site/:slug` 兼容跳转到 `/c/:slug/`。
- 子站页展示 Logo、名称、slogan、简介、统计、关注按钮、发帖按钮、板块导航、置顶、精华、最新、热门、未解决问答、热门标签、版主和公告。
- 页面运行时增强失败时，不应白屏。

## 后台计划

- `/admin-next/communities` 作为子站管理入口。
- `/admin-next/sites` 保持兼容。
- 支持新增、编辑、启用 / 禁用、排序子站。
- 支持配置子站 SEO 和公告。
- 支持查看和管理子站板块。
- 子站和板块操作尽量写入 audit logs。

## SEO 计划

- `/c/:slug/` 成为子站 canonical URL。
- `/site/:slug` 兼容跳转到 `/c/:slug/`。
- `/c/:slug/` 由 Go 动态输出 SEO HTML，不依赖浏览器 JS 才能看到核心内容。
- 禁用或归档子站返回带 `noindex,follow` 的不可用页面。
- `/sitemap.xml` 包含启用子站，不包含禁用或归档子站。
- `/topics/:id` SEO 动态详情页保持不变。

## 文档要求

- 代码、接口、页面、数据结构、SEO、部署、测试发生变化后必须同步文档。
- 不允许只改代码不改文档。

- API 变化同步 `docs/API.md`。
- SEO 变化同步 `docs/SEO.md`。
- 测试和启动变化同步 `docs/TESTING.md` 与 `docs/DEPLOYMENT.md`。

建议至少执行：

```bash

go build -o .devhub/devhub .
./dev.sh --restart
curl http://127.0.0.1:8090/api/v1/health
curl http://127.0.0.1:8090/api/v1/communities/php
curl http://127.0.0.1:8090/api/v1/communities/php/stats
curl http://127.0.0.1:8090/api/v1/communities/php/categories
curl http://127.0.0.1:8090/api/v1/communities/php/tags
curl http://127.0.0.1:8090/api/v1/communities/php/moderators
curl http://127.0.0.1:8090/c/php/
```

## 已知风险

- v1.1.0 使用启用板块生成默认子站导航，深度自定义导航留到后续版本。
- 标签合并、标签别名、标签趋势统计和标签后台管理留到 v1.2.0。
- 完整关注流留到 v1.3.0；本版本完成关注状态、follower_count、动态和我的关注展示。
- 评论点赞、取消已解决状态、推荐系统、声望积分和复杂运营分析不属于本版本。
- sitemap 仍是单文件动态输出，内容规模变大后需要分片。

## 下一版本规划

- v1.2.0：标签系统增强、标签 SEO 聚合页、标签后台管理、标签合并 / 别名。
- v1.3.0：推荐、关注流和内容发现。
- v1.4.0：用户成长、声望和个人主页。
- v1.5.0：后台运营、治理和数据统计增强。
- v1.6.0：生产化、migration、性能和 CI/CD。
